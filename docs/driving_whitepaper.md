## 0. 이 프로젝트에서 반복된 실패 유형 (★먼저 읽을 것)

### P1. 같은 로직이 두 곳에 복제되고, 고친 쪽이 아니라 **낡은 쪽이 이긴다**
가장 비싼 실패다. 세 번 발생했고 매번 몇 시간을 썼다.

| 사례 | 고친 곳 | 실제로 이긴 곳 | 증상 | 비용 |
|---|---|---|---|---|
| 스폰(u_5077, 커밋 b406c64) | `game.js` (강남역 최근접) | `teacher.js:391` (가장 긴 구간, 거리조건 없음) | 매 로드마다 차가 강남역 → 경부고속도로 783m 로 순간이동 | 수 시간, game.js 를 여러 번 고쳤는데 **전부 무효** |
| 보행자 제동 | `driveAuto` (횡 2.2m + 차도점유) | `teacher.js` (횡 4m + 인도필터 없음) | 두 제어기가 매 프레임 다른 '설지 말지'를 냄 → u_5056 과브레이크 | 사고 원인 오진 |
| 배치 정책 | 한 곳 | `pickStart`·`hardReset`·`setStart` 세 곳에 손복제 | 셋이 '우연히' 일치할 뿐이었다 | 잠재사고 |

teacher.js 사례는 특히 나빴다: 그 코드가 자기 `streamWorld(true)` 를 호출했기 때문에
**이동이 스트리밍 코드 탓처럼 보였다**. 화면에서 프레임 사이 좌표를 찍어서야 잡혔다.
```
hardReset ends        (14,-7)    ck=0,-1     <- 강남역, 정상
MOVED_BETWEEN_FRAMES  (14,-7) -> (-711,-291) <- 교사가 덮어씀
parkCar enters        (-711,-291)
```
**규칙**: 정책은 함수 하나에만 둔다. 지금 배치는 `placeCarNear()` 한 곳,
보행자 판정은 `pedBrakeDist()` 한 곳, 상수도 `T.PED = {PED_SLOW_M, PED_STOP_M, PED_CROSS_LAT_M}`
로 공용이다. 고칠 때 "다른 사본이 있나"를 먼저 grep 한다.
그 사본을 정당화하던 주석(“hardReset 이 차를 주차칸에 세워둬서”)은 이미 사실이 아니었다 —
**주석은 낡는다. 주석이 아니라 실행 결과를 믿는다.**

### P2. 고쳤다고 보고했는데 **살아있는 산출물에 반영됐는지 확인 안 함**
game.js 를 고쳐놓고 화면은 그대로인데 "수정 완료"로 넘어갔다. 실제로는 teacher.js 가
덮어쓰고 있었다(P1). 또 서버 캐시 때문에 옛 파일을 보고 있던 적도 있다 —
그래서 `serve.py` 가 `Cache-Control: no-store` 를 강제한다.
**규칙**: 수정 → reload → **화면에서 그 값을 다시 읽어** 바뀐 것을 확인한 뒤에만 완료로 친다.

### P3. 스크린샷을 보고 **추측**함 (계측하고 숫자를 읽지 않음)
- "화면상 경부고속도로 같다" 는 추정 때문에 엉뚱한 곳을 고쳤다 →
  지금은 `window.__startRoad` 에 `도로이름 + 차로수 + 강남역에서 N m` 를 **글자로** 남긴다.
- 건물 끼임(v=0 무한정지)은 화면상 제동 0·앞차 40m·보행자 없음·사고 카운트도 안 늘어서
  원인이 안 보였다. **세 번 헛짚었다.** 계측(bldHit 추적)으로만 잡혔다.
- 하드구속 갇힘도 같은 증상(v=0.2 수렴, 화면상 무증상)으로 세 번 헛짚었다.
**규칙**: 화면에서 재고, 픽셀로 추론하지 않는다(§7).

### P4. 확립된 설정을 안 적어둬서 잃음
정사각 **763x762** 캡처 규격은 오너가 u_4939 에서 이미 확보한 값인데 어디에도
"자율주행 시작 시 이 해상도로 강제" 라고 안 적혀 있었다. 창이 CineBot 작업 후

**규칙**: 오너가 확정한 규격값은 그 자리에서 코드 상수 + 주석(출처 u_번호)으로 박는다.

## 1. 캡처/해상도 규격 — 정사각 763x762 강제

**MUST: 자율주행을 시작하기 전에 창을 규격 크기로 되돌린다.** (`drive_window.py:ensure()`,
`drive_test.py` 가 `--no-resize` 가 아닌 한 항상 먼저 호출)

| 항목 | 값 | 출처 |
|---|---|---|
| 캔버스 | 763 x 762 (정사각) | u_4939, u_5089 재지시 |
| 툴바 높이(논리해상도) | 75 px | `capture.py:34` |
| 창 높이 | 762 + 75 = 837 | `drive_window.py` |
| 창 bounds | {0, 25, 763, 862} | `reload.sh` |

**왜 이 규격인가 — 실측:**
- `kCGWindowImageNominalResolution` 로 캡처하면 Retina 2배를 건너뛰고 논리해상도를
  바로 받는다. 픽셀 수가 **1/4**.
- 실제 주행 루프: **28.9ms(35fps) → 17.9ms(56fps)**.
- cv2 로 1/2 축소하는 단계가 **통째로 사라진다**(추가로 17.9ms → 10.8ms 급 이득 경로).
- 품질 저하 없음: 신호등 542 → 540px, 차선 10.82% → 10.84%, 오차 1.04 → 1.16.
- 단서는 `WindowServer` 가 CPU 1위(**48.6%**)였다는 점이다. `CGWindowListCreateImage` 는
  매 호출마다 WindowServer 합성을 거치므로, 받는 픽셀을 줄이는 게 가장 직접적이다.

**왜 강제해야 하나**: 창 크기가 바뀌면 캔버스 해상도가 바뀌고, 학습/추론의
**입력 분포가 통째로 바뀐다**. 코드픽셀 디코더 위치와 버튼 좌표도 같이 틀어진다.
순서는 반드시 **리사이즈 → 버튼 좌표 재조회**다(`drive_test.py`).

**함정 (실측):**
- AppleScript `bounds` 는 (x1,y1,x2,y2)다. w,h 가 아니라 **오른쪽·아래 좌표**.
  `y2 = y1 + 높이` 로 안 넣어서 캔버스가 762 가 아니라 **737** 로 나왔다.
- `open -na --new-window` 금지 — 호출마다 창이 쌓인다(실제로 3개까지 쌓였다).
  `reload.sh` 는 같은 창의 활성 탭 URL 만 바꾼다(u_5075).
- 창 탐색은 제목만으로 하면 안 된다 — 빈 제목 보조창(270x80)이 잡혀 캡처가 None 이 된다.
  **가장 큰 Chrome 창**을 고른다(`capture.py:find_window`).
- 백그라운드 캡처: `CGWindowListCreateImage` 는 픽셀 수와 무관하게 고정비용 ~6ms
  (8x8 만 캡처해도 **5.96ms**). 전용 스레드로 돌리면 추론루프 478fps, 실제 새 화면 70fps.
  단 **85%가 같은 프레임**이므로 학습 수집은 `seq` 로 새 프레임만 받는다.
- `_to_np` 에서 `[2,1,0]` 팬시 인덱싱은 복사를 만든다(0.6ms). `[:, :W, :3]` 은 view(0ms).
  BGR→RGB 는 GPU flip 으로 처리한다.
- `clear_selection()`: 페이지가 Cmd+A 로 전체선택되면 선택 하이라이트 때문에
  색편향(B-R)이 **+47** 이 된다. 풀면 **+2**(중립). 이 상태로 수집하면 학습 데이터
  전체가 파랗게 물든다. (u_4957 — 당시 '뷰어 오버레이'로 오진했다.)

## 2. 경로탐색 — 상태 = (노드, 진입간선)

`gAstar(s, t, startAng)` (game.js). 핵심은 A* 의 상태가 노드가 아니라
**(노드 n, 그 노드로 들어온 간선 si)** 라는 것이다. 이 확장이 없으면 회전 규칙을
표현할 수 없다.

적용되는 규칙:
1. **제자리 유턴 금지** — `if(si===cur.si) continue`.
2. **일방통행 역주행 금지** — `gSegAllows(sg, cur.n)`. (역주행 **250건 → 0건**)
3. **회전금지(turn restriction)** — `gTurnBlocked(cur.si, cur.n, si)`.
   테이블 1,201건 적재. **금지회전 5/5 차단, 정상회전 20/20 유지.**
   ★순서가 중요하다(오프라인 검증에서 실제로 걸린 버그): `only_*` 키가 같은 테이블에
   들어 있고 그건 '금지'가 아니라 **'의무'** 다. RESTRICT 를 먼저 무조건 막으면
   합법(의무) 회전까지 막혀 **0/20 통과**였다. 올바른 순서:
   ① `only_*` 지정 전이면 즉시 허용 → ② `no_*` 만 단일 금지 → ③ 나머지 `only_*` 역적용.
4. **첫 구간 방향 강제** — `cur.si===-1 && startAng` 일 때 간선 방향과 `startAng` 의 차가
   90°를 넘으면 버린다. 왕복도로는 양방향 통행이 합법이라 A* 가 출발하자마자 같은 도로를
   반대로 되짚는 경로를 만들 수 있고, 그러면 웨이포인트가 **맞은편 차도**에 놓여 차가
   중앙선을 넘어야만 경로에 올라탈 수 있다(u_5048).
5. **가상간선(stitch) 비용 40배** — 실제 도로가 아니므로 최후수단화(u_5024).

경로 채택 조건(`planTo`):
- 출발 후보를 여러 개 시도한다: `gStartNode`(방향 인식) → `gNearest`. 하나만 믿으면
  그 노드가 막다른 곳일 때(일방통행 진행방향 끝점의 **3.1%**) 탐색이 통째로 실패한다.
- 출발노드가 차에서 **60m** 넘게 떨어져 있으면 그건 옆 도로다 → 버린다(u_5038).
- 앞부분 25점 중 도로 위 비율이 **0.8 미만**이면 버린다 — "도로가 아닌 곳을 지나는 경로는
  애초에 경로가 아니다"(u_5035).
- `gStartNode` 는 차 투영점을 실제 노드로 끼워넣어 매칭 정확도를 올린다(p95 **131m → 7.7m**).
  대신 호출의 **57%** 가 그래프를 키우므로, 매 plan 시작 시 `__gBase` 로 원래 크기로 잘라야
  GNODES/GSEGS 가 무한히 자라지 않는다(ar_5051).

### 2.1 차로 오프셋 부호 — ★이 부호는 이미 한 번 거꾸로 알았다

적용식이 `wp = n - sin(ang)*off` 라서 **부호가 뒤집힌다: `off<0` 이면 진행방향 오른쪽**.
실측(언주로 일방 4차로, 반폭 7.0m):

| off | 결과 | 판정 |
|---|---|---|
| **-5.25** | 중심선 +5.25m = 오른쪽 차로 | **정상** |
| +1.75 | 중심선 -1.75m = 왼쪽 반대차로 | 틀림 |

`laneOffset()` 의 일방통행 식이 맞다. **부호를 '고치려다' 오히려 반대차도로 보낼 뻔했고,
계산해보고 되돌렸다**(u_5030). 부호가 이상해 보이면 고치기 전에 위 표를 재현해볼 것.

규칙: 일방통행은 `0.5*LW - lanes*LW/2` (가장 오른쪽 차로), 왕복은 `0.5*LW` (진행방향 1차로).
예전엔 무조건 1.75m 만 띄웠는데 일방통행은 전 차로를 쓰므로 기준이 달라
**실측 오차 5.25~7.0m**, 주행선이 도로 반대쪽 끝이나 도로 밖에 놓였다(u_5025).

### 2.2 코너 기하 — 순서가 전부다

**[리샘플(중심선 5m) → 점마다 자기 국소방향으로 오프셋 → 교차로는 이등분선 호]**

예전 순서(노드를 '떠나는 간선' 방향으로만 오프셋)의 실측 결과(왕복2차로 off=+1.75m, 90°):
- 좌회전에서 꼭짓점 오프셋이 반대 차도(lat=-1.75m)로 들어감 → 중앙선 하드구속이
  위치를 되돌리고 0.9초 뒤 `crash('중앙선 침범')`. **좌회전마다 결정적으로** 발생(간헐 아님).
- 올바른 차로중앙은 이등분선 위 `off/cos(Δ/2)` = **2.47m**.
- 리샘플이 오프셋 뒤에 있어서 교차로 인접 간선(L<25m)은 `floor(L/25)=0` →
  **가장 급한 코너가 가장 성긴 채로** 남았다. 5m 한 칸에 90° → κ≈0.31 →
  `vmaxCurve` 가 하한 3.5m/s 로 눌려 **실재하지도 않는 코너에서 기어갔다.**

호는 반드시 **오프셋된 차로중심선 위에서** 만든다. 중심선에 그린 뒤 오프셋을 더하면
좌회전에서 부호가 뒤집혀 반대 차도로 들어간다(실측: 호 중앙 y=+1.66m → **-1.21m**, 중앙선 관통).

접선길이는 `R*tan` 이 아니라 **`(R+off)*tan(|Δ|/2)`** 다. 원 중심이 이등분선 위
`(off+R)/cos(Δ/2)` 에 있기 때문. `R*tan` 으로 자르면 90°에서 T=6.00m vs 실제 접점 7.63m →
리샘플 점 하나가 호 시작점을 지나쳐 찍혀 **표본당 180° 역주행 스파이크**가 생겼다(u_5057).

회전반경은 차로폭이 아니라 주행 가능한 반경을 쓴다: `RMIN = 6m`(도심 교차로).
`LW/tan(Δ/2)` 는 90°에서 R=3.25m 로 실차 최소회전반경보다 작아 호가 3m 밖에 안 되고
샘플당 **86.7°** 가 남아 곡률 스캔이 폭발했다.

## 3. 출발점 배치 — 정책은 `placeCarNear()` 하나

**모든 배치(pickStart / hardReset / setStart)가 이 함수 하나를 부른다.** 세 곳에 손복제돼
있던 것을 합쳤다(P1 참조).

정책: **강남역에서 가장 가까운 '시가지' 도로** → 2패스 → 건물 없는 t.

- ★**'가장 긴 구간'이 아니다**(u_5073~5076). 가장 긴 구간을 고르면 그 일대에서 제일 긴
  간선대로가 뽑히고, 그건 강남역과 무관하다. 실제로 경부고속도로가 뽑혔다.
  고속도로에서 출발하면 **좌/우회전을 볼 수 없고** 진출로까지 묶인다.
  실측: 강남역(11.4, -9.9) 기준 최근접 = **테헤란로 12.7m**.
- 2패스: 1차는 시가지 도로만, 그래도 없으면 2차에서 고속도로까지 받는다.
- `isCityRoad()` 판정축은 **이름만**(`고속도로|고속화|나들목|분기점|램프|JC|IC`).
  ★**차로수로 거르지 않는다**(u_5076) — 강남대로가 8차로다. 넓다고 고속도로가 아니다.
  이 조건 때문에 강남역 본선이 후보에서 빠졌다.
- metric: `'mid'` = 세그먼트 중점 거리(강남역 기준 배치), `'proj'` = 수직투영 거리(내 위치 스냅).
- 건물 회피: 여러 t 를 훑어 `bldAt()<0` 인 지점을 고른다.

### 3.1 강남역 앵커 함정 (★세 번 지적받음)

| 함정 | 실측 | 대응 |
|---|---|---|
| **'강남역' 접두 검색** | SEARCH 첫 항목 = **강남역리가스퀘어오피스텔 (-286, -370.9)**, 실제 역에서 **460m**, 바로 옆이 경부고속도로 | 정확한 항목 하나 지정: `강남역지하쇼핑센터` (11.4, -9.9) |
| **'원점 최근접'** | 원점이 강남역이란 보장이 없다. 원점 근처를 지나는 경부고속도로가 뽑혔다 | 강남역 좌표를 직접 찍는다 |
| **인덱스 캐싱** | 청크가 바뀔 때마다 `buildGraph()` 가 segs 를 통째로 다시 만든다 → 같은 번호가 전혀 다른 도로 | `reset()` 마다 `pickStart()` 재계산 |
| **스트리밍 순서** | 강남역 도로가 안 올라와 있으면 후보에 고속도로밖에 없다 (실측 'START: 경부고속도로 / 강남역에서 783m') | **좌표를 먼저 옮기고** `streamWorld()` 를 돌린다 |
| **지하 구조물 충돌** | 강남역지하쇼핑센터는 **144x174m** 로 강남대로 위를 덮는다 → 출발 즉시 '건물 충돌' | 지하 구조물을 건물 충돌에서 제외 |
| **parkCar 가 덮어씀** | 'pick:테헤란로@13m → START:경부고속도로 783m' | 스냅 전 `streamWorld(true)`, 스냅 거리 60m 초과면 아예 안 움직임 |

주차칸 출발 금지: `PARK.bays[2]` 는 도로 밖 **13.25m**. 직진해도 도로에 못 닿아 5.5초 만에
도로이탈 — **25판 중 19판이 1.6~2.1초에 죽은 원인**. 수집 데이터도 오염됐다:
**29,121프레임 중 51%가 차로중심 10m 초과(중앙값 13.25m)** — 이게 '좌측통행/차로무시'처럼
보인 원인이다. ⇒ LEARN 이든 아니든 **도로 위에서 출발**한다.

또한 시작 도로를 화면에서 추정하지 말고 `window.__startRoad` 에 이름·차로수·강남역 거리를
글자로 남긴다(u_5074).

## 4. 제어 — 호길이 기반 Pure Pursuit

**웨이포인트 인덱스를 고르지 않는다.** `docs/driving_unsolved.md` 의 실패 6건은 전부
'어느 웨이포인트를 목표로 삼나' 규칙이었고(가까우면/지나치면/최근접/순서대로),
코너에서는 **어떤 규칙도 틀린다**: 모퉁이 너머 점이 더 가깝고, 7m 안에 못 들어오고,
세그먼트 방향이 90°씩 점프해 조향이 포화·진동한다(실측 **307→14→67→29→62→32도**).
게다가 driveAuto 에 선택 블록이 **3개** 겹쳐 서로 싸웠다(그중 하나는 방향 필터 없는
최근접 → 진행률 뒷걸음질의 원인).

구조(`driveAuto`):
- 진행 = 경로 위 **호길이 `auto.s`** (스칼라, 단조증가, 뒤로 못 감. 3m 여유, 프레임당 최대 60m)
- 목표 = `posAt(s + Ld)` 의 보간점 (연속). 세그먼트 점프 없음
- 조향 = `δ = atan(2·wb·sinα / Ld)`, `wb = 차길이*0.6 = 2.76m`, `maxSteer = 0.62rad`
- `Ld = clamp(0.9·v, 6, 16)m` — 정상. **복귀 모드**(xt > 6m)에서는 `clamp(4+0.3v, 4, 8)m`
  로 짧게 잡아 경로에 급히 붙는다 (실측: s=1130m 에서 xt=19.8m 로 밀린 뒤
  df=0.93(53°)로 옆을 겨냥한 채 v=0 정지 — Pure Pursuit 는 경로 위를 전제한다, u_5052)

### 4.1 투영 창 — ★두 번 사고를 냈다

```
lo = auto.s - 20m,  hi = auto.s + 250m
```
1. **창 < 웨이포인트 간격이면 죽는다**(u_5056). 경로 8242m 가 135점 = 간격 **61m** 인데
   창이 **60m** 였다. 다음 구간이 창 밖이라 투영 후보에서 빠지고 s 가 영영 멈췄다.
   계측 하네스가 `wp_idx=4/135, path_dist=0.0` 으로 잡아냈다 — **1m 차이**.
   (진행률 0.038 → 창 수정만으로 0.161)
2. **방향 필터가 필요하다**. 창이 250m 인데 필터가 없으면, 헤어핀이나 되돌아오는 경로에서
   '돌아오는 쪽 구간'의 점이 200m 앞인데도 공간상 가장 가깝다. s 가 한 프레임에 최대 60m
   점프하고 전방주시점이 **반대 차도**에 찍혀 차를 중앙선 너머로 조향했다.
   ⇒ 경로 진행방향과 `me.ang` 차이가 **75°** 넘으면 그 후보는 버린다.

### 4.2 곡률 기반 속도

앞 **25m** 를 **5m** 간격으로 스캔해 최대 곡률 κ(rad/m)를 구하고
`vmaxCurve = clamp(√(2.4/κ), 3.5, 14)` m/s (허용 횡가속 aLat = 2.4 m/s²).
추가 감속: `|α| > 0.6rad` 이면 vmax ≤ 5. 복귀 중(xt>6)에는 vmax ≥ 4.5 로 추진력 유지.

**실측 (70초, 130샘플, 재설계 전/후):**

| 기준 | 이전 | 이후 |
|---|---|---|
| 방향 반전 횟수(진동) | 연속 | **0회** |
| 총 방향변화 | ±30 진동 | 130도 한 방향 |
| 진행률 감소 | 뒷걸음질 | 1회(사고 복귀) |
| 도로 위 비율 | — | **100%** |

### 4.3 교착 해제 — '막혔나'가 아니라 '실제로 못 가나', 단 앞차가 있으면 제외

- `gap()` 은 거리만 본다. 앞차가 서 있으면 gap<11m 이 영원히 유지돼 vmax=0 으로 굳는다.
  실측: 경로·조향 정상인데 v=0.1 로 **70초 내내 제자리**.
- 판정을 '앞이 막혔나'(gap<28m)로 하면, 옆·뒤에 끼인 경우 gap 이 비어 보여 타이머가 안 돈다 —
  실측 1.1km 지점에서 추돌 2회 후 v=0 으로 **140초** 정지(u_5052).
  ⇒ **경로가 남아 있는데 못 가면 이유 불문 교착.**
- ★단 `queued = gap < 14m` 면 교착이 아니다(u_5059). 예전엔 무조건 교착이라
  줄 서 있는 상황에서도 creep 이 **2.2m/s** 를 강제해 **앞차를 그대로 들이받았다**
  (강남→시청 촬영, 램프 합류 대기 중 gp=7m).

## 5. 하드 구속 — 규칙을 '기대'하지 않고 못 어기게 만든다

예전엔 인도 침범을 감속+사고기록으로만 처리해서 차가 실제로는 인도 위를 계속 굴러다녔다
(실측 **25초에 사고 8~23회**). 건물은 이미 하드 구속인데 도로만 물렁했다.

1. **차로 밖 이동 무효화**(u_5027): 직전이 도로 위였는데 이번 이동이 도로를 벗어나게 하면
   위치를 되돌리고 `v *= 0.55`. `offroad > 0.9s` 면 `crash('차로 이탈 시도')`.
   어떤 컨트롤러(경로주행·교사·학습모델)를 써도 물리적으로 차로를 못 벗어난다.
2. **건물 충돌**: 위치 되돌림 + `crash`. 끼임 복구는 §5.2.
3. **중앙선 침범 무효화**(u_5048): 왕복도로에서 진행방향 기준 `lat < -0.6m` 이면 되돌림,
   `v *= 0.5`, `offroad > 0.9s` 면 `crash('중앙선 침범')`.

### 5.1 ★교차로 게이팅 — 이 구속은 '합법적으로 넘어야 하는 바로 그 지점'에서 제일 못 믿는다

`nearestSeg()` 는 폭·방향 조건 없이 전 구간을 훑어 **가장 가까운 중심선만** 준다.
교차로 한복판·램프·나란한 이면도로 옆에서는 그게 **교차하는 다른 도로**다.
그 낯선 구간의 `ang` 로 dir 을 정하고 lat 을 재면 직각에 가까운 중심선까지의 거리라
lat 이 임의로 음수가 되고 → 매 프레임 위치 되돌림 + `v*=0.5` →
**교차로에서 합법적으로 좌회전하던 차가 '중앙선 침범'으로 사고 처리됐다.**

세 관문을 모두 통과할 때만 검사한다:
1. `ns.d <= roadW*0.5` — 실제로 그 도로 위에 있을 때만
2. `|Δheading| < 60°` — 그 구간을 따라 달리고 있을 때만
   (양방향 도로는 저장된 `ang` 방향이 임의라 **180° 접은 값**으로 본다.
   역방향 주행은 반대 차선이므로 정상이다)
3. `!nearJunction(x, y, sg)` — 교차로 노드에서 `roadW*1.5` 안쪽이면 **검사 자체를 끈다**.
   `nearJunction` = 구간 양 끝 노드 중 `XR[n]`(간선 3개 이상 = 교차로)인 것 기준.

**게이팅 효과 (실측):**

| 항목 | 게이팅 전 | 게이팅 후 |
|---|---|---|
| 중앙선 오탐 | **2,352 / 5,028** 프레임 | **18 / 5,028** |
| 실제 역주행 검출 | 31 / 31 | **31 / 31 (유지)** |

즉 오탐을 **99.2% 제거하면서 진짜는 하나도 안 놓쳤다**. 구속을 **완화**해서 푼 게 아니라
**적용 범위를 정확히 해서** 푼 것이다 — 이 구분이 핵심이다.

### 5.2 갇힘 복구 — 구속을 풀지 말고 경로 위로 되돌린다

두 하드구속 모두 '위치 되돌림 + v 감쇠'를 매 프레임 한다. 경로점이 임계선 바로 너머에
있으면 차는 그쪽으로 갈 수 없는데 계속 가려고 해서 **v = 0.2 로 수렴한 채 영원히 멈춘다.**
사고도 안 나고 제동도 0이라 화면상 원인이 안 보인다(**세 번 헛짚은 이유**).

- `blockT > 1.0s` → 경로 위로 복귀. `bldStuck > 1.5s` → 같은 처리.
- ★**막힌 그 점이 아니라 `auto.i + 3` 점 앞으로** 보낸다(u_5056). 같은 점으로 되돌리면
  도착하자마자 같은 구속에 다시 걸려 무한반복 — 실측 wp45 는 통과했는데 wp64 에서 재현.
- 복귀 시 `auto.s = cum[j]`, `auto.k = j` 까지 같이 옮겨야 한다.
- `blockT` 는 감소를 천천히(`-dt*0.5`) 해야 깜빡이는 구속도 누적된다.

## 6. 보행자 — 공용 술어 하나, 25m / 12m / 2.2m

```
PED_SLOW_M      = 25    // 이 안이면 감속 (vmax ≤ 3.5 m/s)
PED_STOP_M      = 12    // 이 안이면 정지 (vmax = 0)
PED_CROSS_LAT_M = 2.2   // 차도 위 보행자: 내 차로 폭만
```

`pedBrakeDist()` **하나**를 교사(teacher.js)와 주행(driveAuto)이 **같이** 쓴다.
상수까지 공용(`T.PED`)이어야 갈라짐이 안 돌아온다. 예전 두 갈래:
- 교사: 횡 **4m** 고정 + 인도 필터 없음 → **건너편 인도에 서 있는 사람에게도 섰다.**
  교차로엔 항상 누가 있어 **영원히 안 풀린다**(u_5056 과브레이크 사고의 원인).
- driveAuto: 횡 2.2m + `!p.cross && !onRoad()` → `p.cross` 플래그가 켜졌다는 이유만으로
  아직 인도에 서 있는 무단횡단자를 차도에 있는 것으로 쳤다.

### ★2.2m 를 넓히면 안 되는 이유
**2.2m 는 u_5056 과브레이크 수정값 그 자체다. 넓히면 그 사고가 그대로 돌아온다.**
그래서 '넓히기'가 아니라 **'차도 점유 여부'(`onRoad`)** 로 푼다.

`p.cross` 플래그는 **쓰지 않는다**. 측정으로 확인한 이유(4차로 roadW=13m, h=8m):
- 무단횡단 시작 순간(cross=1, cx2=0) **off = 8.0m** → 아직 인도다. 플래그를 믿으면
  인도 위 사람에게 제동한다.
- 횡단 완료로 cross=0 되는 순간(|cx2|=cmax) **off = -8.0m** → 이미 건너편 인도다.
  즉 플래그가 꺼질 때 사람은 이미 차도 밖이므로 **플래그를 버려도 놓치는 구간이 없다.**

⇒ `onRoad` 하나가 두 경우를 모두 정확히 가른다.

판정: 전방거리 `f ∈ (0, 25m)` — 뒤에서 걷는 사람 때문에 서면 안 된다 —
**AND** 횡거리 `|l| ≤ 2.2m` **AND** `onRoad(p.x, p.y).ok`.

## 7. 검증 규율

### R1. 화면에서 재고, 픽셀로 추론하지 않는다
좌표·문자열·상태는 계측해서 숫자로 읽는다. 스크린샷 눈대중은 §0 P3 의 모든 오진을 만들었다.
값은 캔버스 좌상단 **코드픽셀 블록**(x=0..15 마커 + 오른쪽 블록들)으로 내보내고
`decode.py` 가 읽는다.

### R2. ★디코더가 `None` 을 돌려주는 조건을 알고 있어야 한다 — 조용히 측정을 오염시킨다
사고 시 화면 전체가 **빨강 opacity 0.92** 로 고정된다(u_4918: 140ms 번쩍임은 판별이
어려웠다). 이 오버레이가 코드픽셀 자리를 덮으면 `find_blocks()` 가 마커를 못 찾아
**`decode()` 가 None 을 돌려준다.** 호출부가 None 을 '변화 없음'으로 흘려보내면
사고 직후 구간이 통째로 측정에서 빠진다 — 이게 이전 측정들을 조용히 오염시켰다.
같은 계열의 사고가 또 있었다: db 가 'Storage full' 배너를 캔버스 상단에 띄웠고
그 배너가 **바로 코드픽셀 자리를 가려** 디코딩이 전부 실패했다(u_4969).
⇒ **`decoded` 카운트를 항상 같이 남기고**(`drive_test.py` 가 `decoded`, `onroad_pct` 를
기록한다), None 비율이 높으면 그 측정은 **버린다**.

### R3. 디코더 자체의 함정
- 마커색 허용오차를 넓히면 **브라우저 툴바(보라 계열)** 가 먼저 걸려 엉뚱한 행을 읽는다
  (`steer=1.00 / brake=1.00` 같은 불가능한 값). ⇒ 마커 + 오른쪽 3블록이 **서로 다른 색**
  이라는 구조를 검사해 확정한다(툴바처럼 균일한 띠면 4칸이 같은 색 → 탈락).
- 전체 프레임(2.6M px)을 float 로 올리면 **25.87ms**. 좌상단 열만 보면 **0.5ms**.
- 캔버스 색상 코드픽셀은 프레임 합성으로 색이 뭉개진다(A55AC3 → 586293) — 그래서
  블록을 16px 로 크게 잡고 중심 픽셀을 읽는다.

### R4. 사고를 종류별로 센다
`cr=8` 만 봐서는 고칠 곳을 모른다. `window.__crk` 가
`추돌 / 보행자 / 중앙선 / 차로이탈 / 건물 / 기타` 로 나눠 센다.
(중앙선은 u_5061 에서 차로이탈과 분리 측정하려고 따로 뺐다.)

### R5. 판정 기준
목표 = **목적지 도착**. 사고가 나면 실패(u_5060), 사고가 없으면 도착까지 간다.
`drive_test.py` 는 사고 카운터가 증가하면 즉시 종료한다.
