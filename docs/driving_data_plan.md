# 자율주행 모델 — 데이터·학습 계획 (u_5140, 2026-09-15)

> 오너: "정말 모델 학습에 필요한 데이터만 남겨. 계획을 세워 자율주행 모델을 만들기위한
> 그거대로 데이터 수집하고 학습하고, 테스트하고를 반복해"

## 0. 원칙
- **주행 주체는 항상 모델.** 수식(driveAuto)이 잘 달린 건 성과가 아니다.
- **로직의 유일한 용도 = 라벨 생산.** 새 능력은 teacher.js 에만 넣는다.
- 성공 기준 = corr/loss 아님. **강남역→시청역 도착, 사고 0건.**
  cf `.claude/rules/model-drives-not-logic.md`

## 1. 현재 데이터 실측 (지우기 전에 잰 값)

| 항목 | 값 |
|---|---:|
| 저장 프레임 | 85,768 |
| **고유 프레임** | **21,677 (74.7% 가 완전 중복)** |
| 좌회전(steer<-0.3) | **108** |
| 우회전(steer>+0.3) | 10,142 |

우회전이 좌회전의 **94배**다. 정지·이탈은 사실상 0이다.
수집이 `--lanedemo` 없이 돌아 교사가 한 차로 직진만 시연했고(BEST_MODEL.md 기록),
게임이 도로이탈을 물리적으로 되돌려서 복구 장면이 남을 수 없었다.

중복 원인은 capture.py 주석에 이미 경고돼 있다: "추론이 캡처보다 빠르므로 같은
프레임을 다시 본다(85%). 수집에는 seq 로 새 프레임만 받을 것" — 지켜지지 않았다.

## 2. 정리 (무엇을 지우고 무엇을 남기나)

| 대상 | 크기 | 처리 | 이유 |
|---|---:|---|---|
| `data/t_hv`, `data/t_hv2` | 15.7G | **삭제** | `data/final` 이 이 둘의 병합본이다. SRC.npy 로 확인(42,716+43,052=85,768). 완전 중복 |
| `data/final` | 16G | **유지 + 중복제거본 생성** | 라벨은 정상(모델 적합 corr .99). 고유 21,677 장만 `data/final_uniq` 로 뽑는다 |
| `data/seoul_backup_*`, `*.bak*` | 51M | 삭제 | 지도 백업, 학습과 무관 |
| `data/osm_src`, `seoul*`, `gyeonggi` | ~630M | 유지 | 지도 원본. 재생성 비용이 크다 |

★`data/final` 원본은 지우지 않는다. 중복제거는 **인덱스 기반 새 파일**로 만들고
원본은 그대로 둔다. 되돌릴 수 없는 삭제는 하지 않는다.

## 3. 수집 계획 — 결손만 채운다

교사 모드는 이미 있다(`kb_teach` = fwd|left|right, `--lanedemo`, `--sigdemo`).

| # | 상황 | 목표(고유) | 방법 |
|---|---|---:|---|
| C1 | 좌회전 | 8,000 | `kb_teach='left'` — 교차로에서 좌분기 선택 |
| C2 | 차로변경 L/R | 8,000 | `--lanedemo` |
| C3 | 추월 | 6,000 | teacher.js 추월 로직(u_5123) + 느린 앞차 배치 |
| C4 | 정지→출발 | 4,000 | `--sigdemo` 적신호 |
| C5 | **이탈 복구** | 10,000 | `__COLLECT_RECOVER` — 되돌림 끄고 교사 복귀 녹화 |

합계 36,000 고유. 기존 21,677 + 36,000 = 57,677.

**수집 규칙(이번엔 지킨다)**
- seq 로 새 프레임만 받는다. 중복 저장 금지.
- 교사 ON 확인. 꺼져 있으면 라벨이 언다(실측: 278프레임에 조향값 2종류).
- 수집 중 `rev != 0` 이거나 라벨이 고정이면 **즉시 중단**.

## 4. 학습
- 결손 구간 가중 균형 샘플링. 단순 concat 은 기존 데이터가 지배한다.
- GPU 필수(`gpu_guard.require_gpu()`). CPU 폴백 금지.
- DAgger: 모델이 몰고 교사가 정답 라벨 → 모델이 실제 가는 상황의 정답을 얻는다.
  ★기존 `dagger_run.py` 는 못 쓴다: 화살표키로 조작(경로 주행 중 무시됨)하고
   **교사 라벨을 저장하지 않는다.** `/tel` 에 교사 출력을 노출시켜 다시 만든다.

## 5. 반복 루프
```
수집 → 학습 → 모델로 주행 측정(도착·사고) → 결손 분석 → 수집
```
매 회 기록: 고유 프레임 수, 구간별 비율, 헤드별 corr, **도착률·사고수**.
도착률이 안 오르면 corr 이 올라도 실패로 본다.

## 6. 오드 v2 실패 기록 (u_5162, 2026-09-16)

학습 지표는 전부 좋았는데 주행은 v1보다 나빴다. 이 절은 그 이유를 남긴다.

| | 오드 v1 | 오드 v2 |
|---|---:|---:|
| val loss | — | **0.0347** (0.142에서) |
| 베이스라인 대비 | — | **82.7% 개선**, 판정 LEARNED |
| 실주행 진행률 최고 | 0.911 | **0.0** |
| 사고/에피소드 | 1.43 | **17** |

### 진단 (측정, 추측 아님)
- 새 커리큘럼 데이터에서 조향 상관: v1 **0.079** → v2 **0.863**
  ⇒ 좌회전·차선변경·복구는 **제대로 배웠다.**
- 실시간 출력: **thr=0.109, brake=0.790** ⇒ 차가 안 움직인다.

### 원인
커리큘럼은 차를 일부러 세우고 밀어낸다. 그래서 급제동(brake>0.5) 비율이
원본 0.5% 대비 **이탈복구 21.2% / 정지출발 19.7%** 다.
여기에 6~12배 가중치를 주니 배우게 하려던 '복귀 조향'만이 아니라
**'멈추는 동작'까지 같이 증폭**됐다. 스로틀 평균 0.812 → 0.643.

### 조치 (v3)
1. 가중치 12배 → **1~4배**
2. **'급제동 + 저스로틀' 프레임 제외** — 그건 연출이지 상황대처가 아니다
3. **학습 전 분포 검증**을 절차로 고정

| 세트 | thr 평균 | brake>0.5 | 좌:우 |
|---|---:|---:|---:|
| 원본 final_uniq | 0.812 | 0.5% | 1:94 |
| v2 (실패) | 0.643 | 7.2% | 1:9.3 |
| **v3** | **0.754** | **0.4%** | **1:17.4** |

### 규칙으로 남길 것
- **지표로 합격 판정하지 않는다.** 기준은 도착·사고뿐이다(`eval_ode.py`).
- **수집 데이터를 증폭할 때는 그 데이터의 부작용도 같이 증폭된다.** 분포를 먼저 본다.
- 실패를 '안 배웠다'로 단정하지 말 것. 헤드별로 나눠 보면 조향은 배웠는데
  스로틀이 망가진 경우가 있다.
