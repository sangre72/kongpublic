## 문제점

### P1. 조향이 거의 항상 포화 상태다 ★가장 심각
- 실측: **|steer|>0.95 인 프레임이 96%**, >0.8 은 97% (2,360프레임)
- 화면상 차는 도로 위를 정상 주행 중 → '핸들을 끝까지 꺾은 채로 억지로 직진'
- 학습 데이터로 쓰면 조향값이 사실상 상수(±1)라 모델이 조향을 못 배운다.
  이전에 COLLAPSED 났던 것과 같은 구조의 위험.
- 원인 미확정. 새 지도(278청크)로 바꾼 뒤 나타났을 가능성 — 이전 측정은
  steer +0.15~0.30 / std 0.25~0.39 로 정상 범위였다.

### P2. 목표속도를 못 따라간다
- 설정 `__TARGET_KMH=50`, 실측 **중앙값 21km/h (목표의 42%)**
- 내가 이전에 '목표의 88~90%'라고 보고한 것과 어긋난다. 그때는 강남 80청크였다.
- P1(조향 포화)의 결과일 수 있다 — 커브 감속 로직이 계속 걸리는 상태.

### P3. 새 지도에서 POI·횡단보도가 사라졌다 (회귀)
- 기존 data6.js: POI **60건**, XWALK **45건**
- 새 data6.js: POI **0건**, XWALK **0건** (pack_map.py 가 빈 배열로 내보냄)
- 영향:
  · 보행자 횡단보도 횡단이 동작하지 않는다(buildCross 가 XWALK 를 읽음)
  · 검색 인덱스에 명소(poi) 0건 — '코엑스 아쿠아리움' 같은 명소 분류가 사라졌다
    (건물명으로는 여전히 검색되지만 종류 표시가 '명소'→'건물'로 바뀜)
- pack_map.py 를 만들 때 청크 파일에 POI/XWALK 가 없어서 빈 배열로 둔 것.
  원본 pbf 에는 있으므로 pbf_to_chunks.py 에서 같이 뽑아야 한다.

### P4. 버튼을 바꿔도 이미 보낸 메시지의 버튼은 옛 동작을 유지한다
- 텔레그램 인라인 버튼은 메시지에 박혀 저장된다. 코드 변경 후 새 메시지를
  보내지 않으면 사용자는 '버튼이 안 먹는다'고 느낀다. 실제로 이번에 발생했다.
- 지금은 내가 수동으로 새 메뉴를 보내야 한다.

### P5. 확인 단계가 없다
- [■ 중지] 처럼 되돌리기 어려운 버튼도 한 번 누르면 즉시 실행된다.
