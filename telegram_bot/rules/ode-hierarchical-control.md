# 오드 계층형 제어 — 난이도 등급 라우팅 (오너 결정 u_5436, 2026-09-19)

> 오너: "모델 정밀도가 아니라 주행 시나리오/판단 자체를 난이도별로 등급화해서 처리 전략을 다르게" — ODD 등급화·계층형 컨트롤러(Waymo/Mobileye 식).
> [[model-drives-not-logic]] 의 '주행 주체는 모델' 원칙은 **Layer 2** 에 그대로 적용된다. Layer 1·3 은 규칙이 맡는다(오너 승인).

## 레이어 ↔ 우리 코드
| Layer | 역할 | 담당 | 현재 코드 | 상태 |
|---|---|---|---|---|
| 1 반사(최우선) | 충돌 임박 제동: 앞차·보행자·적신호 | 규칙, 모델 출력과 무관하게 항상 | `teacher.js` compute() 의 제동부(obstacleAhead/pedAhead/signal), `driveAuto` gap/ped 상한 | 분리·페일세이프화 필요 |
| 2 전술 | 차선유지·추종·차선변경·회전 | 학습 모델(단계별) + 규칙 가드(차로·법규) | `train_stage.py` 단계(straight→follow→ped→signal→turn→uturn), `laneTarget` 가드 | 1단계 학습 중 |
| 3 전략 | 경로·회전차로 준비·유턴 구역 | 규칙(라우터) | `planTo/gAstar`, Lprep/Rtl/Stl/Lexit | 운영 중 |

## 등급 판정기(dispatcher) — 프레임마다
- 입력 = 상황 태그 `M.npy` 열과 동일: gap(앞차 m), ped(보행자 m), sig(적신호 m), turn(S/L/R/U), aD(회전까지 m), v, laneF, nl.
- 등급: **T0 쉬움** = 직진·gap>60·ped>40·sig>60 → 모델(1단계) 단독. **T1 중간** = 추종/회전 준비/차선변경 → 모델(해당 단계) + 규칙 가드. **T2 어려움** = 보행자 근접·신호 정지·골목 → 모델 + Layer 1 상시 개입 + 감속. **T3 엣지** = 정지거리 안 돌발·이탈·미분류 → Layer 1 단독(페일세이프), 모델 출력 무시.
- **오판 방향은 항상 상위 등급**(어려운 걸 쉬운 걸로 오판하는 게 위험, 오너 지적). 확신도(모델 출력 분산/ensemble·보조 헤드)가 낮으면 한 등급 올림.
- 텔레메트리: `/tel tier`, 등급별 사고·법규 위반 집계 → 스윕/회귀에 등급 열 추가.

## 검증 기준
- 등급별로 잰다: T0 차선유지·속도, T1 회전차로 준수·추종 간격, T2 보행자 정지율·신호 위반 0, T3 개입 횟수(줄어야 함).
- 등급 판정 자체의 정확도(사후 라벨: 사고 3초 전 등급 분포)를 본다 — 사고 직전 등급이 T0 였다면 판정기 결함.

## 순서
1) 밤샘 교사 수집 → 2) 1단계(직진) 학습·검증 → 3) Layer 1 페일세이프 분리 + 판정기 구현(/tel tier) → 4) 등급별 실측 → 5) 2단계 이후 학습.

## 지연시간 설계 (오너 u_5437, 2026-09-19)
- **트리거는 극경량**: 별도 분류 모델 없이 프레임 태그(gap/ped/sig/turn/aD)로 등급 판정 — 페이지 JS, µs. 등급 판정이 병목이면 이미 늦다.
- **캐스케이드**: 소형(DriveNet 256px, MPS 0.26ms/frame 실측) 상시 → 확신 낮음/T2 에서만 큰 모델로 escalate(데이터 확보 뒤).
- **병렬 페일세이프**: Layer 1 제동은 모델 응답을 기다리지 않는다(이미 매 프레임). 추가: 모델 명령 타임아웃 100ms → 보수 기본(감속·차선유지).
- **투기적 예열**: T1 진입 조짐(aD<200, gap<60)이면 큰 모델을 미리 워밍업(구현 시점: 큰 모델 도입 때).
- ★**실측 병목 = 캡처**: 추론 0.26ms 인데 `capture.grab_canvas`(screencapture 경로)가 ≈700ms → 1.3fps. 캐스케이드보다 먼저 캡처를 10fps↑로.

## 환경 간 커리큘럼·도메인 전이 (오너 u_5438, 2026-09-19)
- 오드(2D)는 저비용 프로토타입. 이후 3D(포르자 호라이즌·ETS2/ATS)로 확장해 학습. 등급 = 환경 간 커리큘럼:
  Tier1 오드 직진/차선유지 → Tier2 오드 상황별(추종·보행자·신호·회전) → Tier3 3D 기초(직진·차선) → Tier4 3D 복잡(교차로·야간·우천·정체).
- 상태 채널은 **텔레메트리 하이브리드**: 오드 = 화면(모델 입력) + `/tel`(상태·라벨). 3D = 화면 + UDP(포르자)/SDK 플러그인(ETS2) 텔레메트리. 화면 인식은 조작 쪽, 상태는 텔레메트리.
- 프레임 태그 `M.npy` 에 **도메인 열**(env: 0=오드, 1=포르자, 2=ETS2) 추가(2026-09-20, 밤 수집 형식 유지 위해 내일). 학습 병합 시 (난이도×환경) 가중 독립 조절.
- 3D 단계에서 HUD 판독 전용 경량 서브모델(속도계·미니맵) 필요 가능 — DriveNet 과 별개.
- DAgger 는 그대로 이식: 오드에서 기초 조향을 먼저 배워두면 3D 에서 개입 빈도가 줄어 수집 비용이 준다.

## 비전 전용 원칙·특권 정보 (오너 u_5439, 2026-09-19)
- **배포 모델(DriveNet) 입력은 끝까지 화면 픽셀만.** `/tel`·teacher.js 의 내부 상태(좌표·주변 차량)는 **라벨 생성용**으로만(Learning by Cheating). 이미 그 구조다.
- 세 도메인 공통 전처리(해상도·정규화)는 `net.preprocess` 한 곳.

## 증강은 후처리로, 난이도는 두 축으로 (오너 u_5440, 2026-09-19)
- 2D 오드에는 조명·그림자가 없다 → 게임 렌더를 건드리지 않고 **학습 파이프라인에서 캡처 후 증강**: `train_stage.py augment()`
  (밝기·대비 지터, 가우시안 노이즈, 25% 흑백, 채널별 색 지터, 30% 흐림(다운→업샘플), 30% 가림 사각형). 학습 배치에만, 추론엔 절대 안 건다.
- 역할 분담: **행동 난이도 = 오드**(직진 < 차선변경 < 끼어들기 < 다중 회피), **시각 난이도 = 3D 게임**(맑음 < 흐림/그림자 < 야간 < 우천/역광).
- 캡처 모듈은 `capture.py`(dagger.py·model_drive.py 가 공용). 증강은 거기가 아니라 학습 배치 로드 직후(`train_stage.batch(train=True)`)에 건다.
- game.js 현재 상태(2026-09-19): 고정 낮·고정 색·고정 해상도. 변하는 것 = 교통량·무단횡단 확률뿐 — 그대로 둔다.
