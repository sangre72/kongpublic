# 어제 되던 것을 먼저 찾는다 (MUST — u_5382/u_5384, 2026-09-18)

> 오너: "어제 그렇게 했는데 어제 레시피를 찾던가 엉망이내."
> 오너: "잡레시피 엉망이내."

## 규칙
반복 잡(운세 업로드·첫댓글 등)을 시작하기 전에 **이전 회차의 실제 실행 산출물을 먼저 찾는다.**
레시피 문서만 읽고 "대충 이렇게 하면 되겠지"로 스크립트를 새로 쓰지 않는다.

1. `protocol/ar/ar_*.txt` 에서 직전 회차 보고서를 찾는다(TOOLS 절에 스크립트 경로가 적혀 있다).
2. 그 경로의 스크립트를 **복사해서 경로만 바꿔 쓴다**. 로직을 다시 짜지 않는다.
3. 도구가 세션 임시경로(scratchpad)에 있으면 **레포 안으로 옮긴다**. 다음 세션이 또 못 찾는다.

## 왜 (실측)
2026-09-18 09-19 배치: 첫댓글 도구가 이미 있었는데(ar_5328 TOOLS 절에 명시) 찾지 않고
새로 만들다 **40분 낭비**했다. 새로 만든 경로 2개가 전부 막다른 길이었다:
- studio.youtube.com/video/<id>/comments → 내 채널 댓글을 아예 안 보여준다(등록됐는데 "없음"으로 보임)
- youtube.com/watch?v=<id> → 댓글 지연로딩 + 자동재생이 남의 영상으로 넘어감

정답은 `youtube.com/shorts/<id>`(우측 댓글패널) 하나뿐이었고, 어제 스크립트에 그렇게 적혀 있었다.

안 열어봤으면 아직 시작할 단계가 아니다.
