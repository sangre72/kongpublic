# 주행은 모델이 한다. 로직은 수집 도구일 뿐 (MUST — u_5124/u_5125, 2026-09-15)

> 오너: "로직으로 가는건 전혀 필요 없음. 데이터 수집용으로 로직 사용한다면 그건 허용함"
> 오너: "자율주행 모댈에 강화 학습해야해"

## 규칙
- **평가·데모·성공판정의 주행 주체는 항상 모델이다.** driveAuto(Pure Pursuit)·teacher.js 로
  잘 달렸다는 건 성과가 아니다. 그건 내가 수식을 잘 짠 것이지 학습된 게 아니다.
- **로직의 유일한 용도 = 학습 데이터 생산(교사 시연)과 그 라벨링.** 그 외 목적의
  로직 주행 개선은 하지 않는다.
- 새 주행 능력(추월·차선변경·복귀 등)을 넣을 때는 **반드시 teacher.js 에** 넣는다.
  driveAuto 에 넣으면 라벨에 안 남고 모델은 영원히 못 배운다(u_5123 실사고).
- 성공 기준은 상관계수·loss 가 아니라 **모델이 실제로 목적지에 도착, 사고 0건.**

## 왜 (실측 근거)
- BC 는 교사를 복제할 뿐 넘어설 수 없고, '도착'이라는 개념 자체가 없다(프레임별 모방).
- 학습 8.5만 프레임 전부 on_road=1.00 → 교사가 이탈 복구를 시연한 적이 없다.
  BC 로는 구조적으로 복구를 못 배운다. 실제 사고의 **100% 가 차로이탈**이다.
- 실시간 조향 상관 0.011(잡음)이어도 BC 는 자기가 실패 중인 걸 알 방법이 없다.
⇒ 결과(도착·무사고)를 최적화하는 강화학습이 필요하다.

## 함정
보상을 '사고 없음'으로만 주면 **서 있는 게 최적**이 된다. 실제로 지금 v=0, 사고 0 상태가
나온다. 진행·도착을 반드시 보상에 넣고 정체를 벌점화한다.

## 보완(오너 u_5436, 2026-09-19)
계층형 제어를 채택했다 — 이 원칙은 **Layer 2(전술: 차선유지·추종·회전)** 에 적용된다. Layer 1(충돌 임박 제동, 규칙 페일세이프)과 Layer 3(경로 계획, 라우터)은 규칙이 맡는다. 상세 [[ode-hierarchical-control]].

## 목표 재확인·무중단 진행 (MUST — 오너 u_5621, 2026-09-24)
> "우리의 목적은 새로운 기기더라도 새로운 코스가 나오더라도 스스로 주행하는 것. 나한테 물어보지 말고 바로바로 계속 진행. 실제 성능 계산과 목표대로 될 때까지 계속."
- **목표 = 처음 보는 기기·코스에서 자율주행.** 장소 기억·고정 코스 최적화는 성과가 아니다(u_5596/u_5598).
- **오너에게 묻지 않는다.** 결정은 실측 근거로 orch/worker 가 내리고 계획서(PLAN_ODE)에 기록, 텔레그램은 이벤트 보고만.
- **멈춤 조건 = 합격선 통과 또는 오너 지시뿐.** 밤·주말 무관. 실패는 즉시 보고하고 다음 수로 넘어간다.
- 합격선(미학습 20구간×300초): 회피가능 사고 0·이탈 0·진폭 p95 ≤0.35m·반전 ≤6/분·복귀 ≤1/구간·전환 ≤2/분.
- 진행 원칙: 오프라인 관문 → 3구간 → 20구간(u_5602). GPU 직렬(u_5581). 결정 기록 §10.
- ★추가 합격 조건(오너 u_5632, 2026-09-25): **고속(14m/s 까지 속도별 전부)과 완만 커브도 같은 기준**으로 통과해야 한다. 저속·직선만 통과한 것은 통과가 아니다. 커브 지표 = 코너 구간 조향율 p95 ≤ 규칙의 1.5배, 횡편차 p95 ≤0.35m.
