## 다음에 할 일 (우선순위 순)

### 1. 데이터 재수집 → 재학습  ★여기부터
지금까지 모은 데이터는 전부 폐기했다. 이유:
- c2/c3: 차가 주차칸(도로 밖 13.25m)에서 출발해 51%가 이탈 상태
- c4: 사고 후 주차칸으로 리셋돼 90%가 lane=13.01m 로 고정
- 위 원인(hardReset)은 모두 수정 완료. 이제 다시 모으면 된다.

    python3 games/seoul-drive/build.py            # 교사 ON
    # 아티팩트 배포 → Chrome 리로드
    python3 games/seoul-drive/collect_screen.py <out> 420
    # 검증: on_road_pct 가 95% 이상이어야 함. 아니면 수집 중단하고 원인부터.

### 2. 자기지도학습으로 전환 (오너 지적 u_4960)
라벨을 미리 주는 방식은 '처음 보는 공터'에서 안 통한다.
사람이 라벨 안 붙여도 되는 신호 3가지로 바꾼다:
  a) 지나간 궤적 = 주행가능 (양성 샘플, 공짜)
  b) 충돌·이탈 지점 = 주행불가 (음성 샘플, 공짜)
  c) N초 뒤 자기 위치 예측 = 주행가능 영역을 이해해야 맞힐 수 있음
게임의 onRoad() 는 학습에 쓰지 말고 채점용으로만.

구조 변경 필요: 현재 망은 global average pool 로 공간정보를 버려서
'어디가 갈 수 있는 곳인지'를 표현할 방법이 없다.
  → 출력에 주행가능 마스크 헤드 추가 (파라미터 +0.1%, 특징추출기 공유)

### 3. 도메인 랜덤화 (u_4956 실측 근거)
색만 바꿔 넣었을 때 조향 변화(범위 -1~+1):
  대비 절반 0.502 ← 치명적 / 밝기±30% 0.15~0.17 / 색조 0.091
색조보다 대비에 3배 민감. 안개·역광이 실제로 위험한 상황인데 거기서 무너진다.
학습 시 밝기·대비·색조를 매 프레임 무작위 변형. 추론 비용 증가 없음.

### 4. 그 다음 (오너가 정한 순서, u_4958)
주행가능 영역 → 차선 유지 → 통행방향 → 신호등 → 낙하물/보행자 → 주변차량

## 미해결
- DAgger: 파이썬이 백그라운드로 밀리면 키 입력이 게임에 안 들어간다
  (readout K=---- 로 확인). 명령 타임아웃 120s 때문에 포그라운드 유지가 안 됨.
  → 수집을 60초 이하로 쪼개거나 별도 터미널 세션 필요.
- 신호등: 데이터는 100개 확보했으나 교사가 고속도로 본선만 달려 실제로 안 만난다.
  목적지 주행을 켜면 교차로를 지나므로 그 상태로 수집해야 한다.
- 브라우저 db 용량 초과(run 66개). 라벨은 화면 코드픽셀로 옮겼으니 지장 없지만,
  db 를 쓸 일이 생기면 먼저 정리해야 한다.

## 함정 (반복해서 당한 것들)
- build.py 수정 시 파일 쓰기 코드 날리지 말 것. 빌드는 '완료'라고 뜨는데
  index.html 이 안 바뀐다. 이것 때문에 길찾기 알고리즘을 엉뚱하게 의심했다.
- 캡처 전 텍스트 선택 해제 필수. 전체선택 상태면 화면이 파랗게 물든다
  (capture.clear_selection() 이 자동 호출하지만 수동 확인 권장).
- 수집 후 반드시 on_road_pct / lane_median 먼저 볼 것. 스냅샷 몇 장으로
  '잘 된다'고 판단하면 안 된다 — 실제로 세 번 그렇게 속았다.
- 게임 탭은 1개만. 여러 개면 각자 게임이 돌아 CPU 를 나눠 먹는다.
