## 1. 추출기에서 바꾼 것 (게임 땜질 아님)

### (A) 비대칭 왕복도로 — `lf`/`lb`
- OSM `lanes:forward ≠ lanes:backward` 인 왕복도로(남대문로 218923156 / 424940172 = 5/3)를 지금은 8 을 4/4 로 그려
  중앙선이 OSM 축 위에 놓였다. 실제 중앙선은 축에서 `(lb−lf)·LW/2 = −3.25m` 옆이라 한쪽 차도가 반대 차도를 문다(오너 관측).
- 규칙: 한쪽만 태그면 나머지 = `lanes − 그쪽`. 양쪽을 알면 `lanes` 태그로 취급(`ld` 아님 → 형제/병합 규칙이 폭을 못 건드림).
  레코드에는 **비대칭일 때만** `lf`,`lb` 를 싣는다. 없음 = 대칭(하위호환). 일방·대칭 레코드의 `lf`/`lb` 는 더 이상 싣지 않는다.
- `l` 상한 10 과 맞춤: 소공로 383097722/781985788 은 7+4=11 → 6/4 (보고서 `asym cap10`).
- 방향별 태그가 있는 way 는 일방 연속성 규칙(`oc`)에서 제외(진짜 왕복).
- 실측: 전체 추출 300 way(secondary 86·tertiary 80·primary 57·residential 52…), 팩 안 88 way.
  중앙선 오프셋 분포 c: ±1.62m 243 · ±3.25m 49 · ±4.88m 8.
  값이 바뀐 way(팩): 후암로 516163750/1339655669 lb 도출 2, 소월로2길 1339655670 lb 3, 탄천동로 477958936 l 4→3(태그 취급으로 병합 규칙 해제), 자양로 1198651840 8→7, 소공로 2건 7/4→6/4.

### 청크 분할 조각 결함(덤으로 잡힘)
- 청크 경계에서 쪼개진 조각(`pc`)에 `od`/`lk` 가 안 실려 있었다 → 경계를 넘는 way 는 일방 연속성·연결로 규칙 대상에서 통째로 빠졌다.
  수정 후 팩의 `od` 20,541→25,735, `lk` 1,538→1,984. 연속성 +1(75→76).

### (B) `*_link` 연결로 일방 추론 — `ol`(+`rv`,`dq`)
- 대상: `highway=*_link`, `oneway` 미태그, 길이 3~300m, **양 끝점이 서로 다른 일방 way 의 점(≤1m)에 닿음**.
- 방향 검사(신규): 끝점에서 닿은 차도의 진행방향과 연결로 첫/끝 선분의 cos.
  뚜렷한 끝(|cos|≥0.15)이 하나라도 있으면 그 부호를 따름(음수 = 거꾸로 그려짐 → 점열·`nd` 뒤집고 `rv:1`).
  두 끝이 반대 부호 = 모순 → 보류. 두 끝 다 직각(분리대 사이 횡단 연결로) = 그린 방향 유지 + `dq:1`(방향 미검증).
- 겹침 검사(신규, 전 구간): 가운데 구간(양 끝 min(5m, L/3) 제외)을 2m 간격 표본 → 닿은 두 차도를 뺀 **모든** 도로에 대해
  같은 방향(±20°)이고 간격 < (폭₁+폭₂)/2 − 1m 이면 보류. 격자 색인(50m)으로 1,500×30만 점 전수 스캔 제거.
- 실측(전체 추출): 후보 129 → **일방화 11**(뒤집음 3, 방향 미검증 4), 보류 118 = 끝점이 일방 위 아님 68 · 겹침 33 · 방향 모순 17.
  팩 안 일방화 3: **1214479814(서소문로/통일로, 오너 예시, L17, 516948898↔773066532, dq)**, 913174022, 1243077198.
- 같은 날 새벽 첫 판(uncommitted, 현재 data6.js 에 반영된 것)은 방향·전구간 겹침 검사 없이 60 건을 뒤집었다. 그중 팩 안 6 건이
  이번 규칙에서 보류로 돌아간다(579996456·1125785345·1219896736 겹침, 913833410·1243077201·1243077202 방향 모순/겹침).
  예: 52872216 motorway_link cos 1.00/−0.76 — 한쪽 끝은 역방향이라 일방으로 두면 라우터 연결이 끊긴다. 보수 쪽이 맞다.
- 겹침 보류 33 건은 대부분 **나란한 연결로 두 개가 5m 간격**(908686280↔1106012339 류) = 이미 겹쳐 그려진 지도. 일방화해도
  새 겹침은 아니지만 규칙대로 두었다. 지도 자체 결함으로 별도 목록(보고서 `link_skipped`).
- 예시 교차로의 `residential 통일로` 464233648(왕복 2차로, 미태그, 773066532 노드에 0.0m 로 합류)은 `*_link` 가 아니라 규칙 밖 —
  **관측만, 변경 없음.** 이름 있는 residential 토막을 일방화하려면 별도 결정 필요.

## 3. game.js 변경 명세 — (A) 를 화면·주행에 반영 (game.js 는 다른 담당, 여기선 스펙만)
공통: 세그먼트에 `lf`,`lb` 를 싣고 중앙선 오프셋 `c` 를 한 번 계산한다. 없으면 `lf=lb=floor(l/2)`, `c=0` (현재와 동일).
```
// buildGraph(로컬 segs, L133 부근) / GSEGS push(L1040) 양쪽
const lf = w.lf ?? Math.max(1, Math.floor(_lf/2)), lb = w.lb ?? Math.max(1, Math.floor(_lf/2));
const c  = w.o ? 0 : (lb - lf) * LW / 2;       // OSM 축 → 실제 중앙선, 진행방향(way 방향) 오른쪽 +, px 단위(LW 는 이미 S 배)
segs.push({..., lf, lb, c});                  // GSEGS 도 같은 세 필드
```
1. `laneOffset(s,dir,lane)` (L397): 왕복 분기를
   ```
   const my = dir>0 ? s.lf : s.lb;            // 내 방향 차로수
   const k  = Math.max(0, Math.min(lane, my-1));
   const cs = dir>0 ? s.c : -s.c;             // 내 진행방향 기준 중앙선 위치
   return cs + (dir>0 ? (k+0.5)*LW : -((k+0.5)*LW));
   ```
   로 바꾼다(일방 분기 그대로). 대칭이면 `c=0`, `my=floor(l/2)` 라 현재 값과 동일.
2. `laneOff(sg)` (planTo 안 L1669~): 왕복의 `myLanes` 를 `Math.floor(l/2)` 대신 **진행방향에 따라 `sg.lf` 또는 `sg.lb`** 로,
   반환값에 `±sg.c` 를 더한다(세그먼트 진행방향 == way 방향이면 `+c`, 반대면 `−c`). `lnOf`·Lexit/Lhold/Lprep 등 차로 번호→오프셋을
   만드는 모든 작성자가 이 함수를 거치므로 한 곳만 고치면 된다. `sg.roadW` 는 `l*LW` 그대로(도로 전체 폭은 불변).
3. 중앙선 그리기 (draw, L4330~): `for(let i=1;i<s.l;i++){ off=(i-s.l/2)*LW; mid = !s.o && i===midIdx }` 를
   ```
   const midIdx = s.o ? -1 : s.lb;            // way 방향 기준 왼쪽(backward) 차로 lb 개 다음 선이 중앙선
   for(let i=1;i<s.l;i++){ const off=(i-s.l/2)*LW; const mid = i===midIdx; ... }
   ```
   (`(i−l/2)·LW` 에서 `i=lb` 이면 `off=(lb−(lf+lb)/2)·LW=(lb−lf)·LW/2=c` — 같은 식.) 대칭이면 `lb=l/2` 라 현재와 같다.
4. `_wrongSide` / 중앙선 하드 구속 (L3858~3880): `lat`(세그먼트 축 기준 부호거리, 진행방향 오른쪽 +)에서 `cs = dir>0 ? s.c : -s.c` 를 뺀
   `latC = lat − cs` 로 판정한다. `_halfLane` 은 `(s.roadW*0.5)/floor(l/2)*0.5` 대신 `LW*0.5` (차로폭 반, 현재값과 동일 의미).
   경로점 기준 `latR` 도 같은 `cs` 를 뺀다. 도로 밖 판정(|lat| ≤ roadW/2)은 그대로(폭 불변).
5. `teacher.js` L116·L742 `nl = sg.o ? sg.l : floor(sg.l/2)` → `dir>0 ? sg.lf : sg.lb`, `nlat`(L524) 도 `−cs`. `roadLimitKmh`(방향당 1차로 판정)도 같은 `nl`.
6. 텔레메트리: `/tel` `wpDbg.offTab` 에 `lf/lb/c` 열 추가 → 회귀에서 `|오프셋 − cs| ≤ 내 차도 폭` 검사.
검증 케이스: 남대문로 218923156 구간(5/3) sx 출발 → 경로 오프셋이 축 −3.25m 기준 오른쪽 차도 안, 중앙선이 축에서 3.25m 옆에 그려지는지 캡처.
