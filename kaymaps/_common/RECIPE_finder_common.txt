RECIPE: finder_common(macOS Finder — 파일 탐색/경로 이동 공통, NSOpenPanel 포함)
REG: a_1060(2026-08-20) — a_1049~1057 경로탐색 반복지연(컬럼뷰 클릭탐색) 관찰 후 강화.
WHY: 컬럼뷰 클릭탐색(홈→상위폴더 클릭 반복)은 느리고 오클릭 위험 큼(다른 폴더 진입, 검색필터 잔류 등). "폴더로 이동" 메뉴가 훨씬 빠르고 100% 정확.

★★핵심 규칙: 목표 절대경로를 이미 알고 있다면(project.json 등에서 확보) 컬럼뷰 클릭탐색 절대 시도하지 말고 반드시 "폴더로 이동" 먼저 사용.

STEPS("폴더로 이동" 사용법, ⌘⇧G 3키조합은 kongtrol chord 미지원 — 메뉴 경유 필수):
1. Finder 창(또는 NSOpenPanel 파일선택 다이얼로그도 동일 작동 확인됨, a_1060) 활성화.
2. 메뉴바 "이동"(Finder 앱 메뉴, 좌측에서 5번째 정도 — a11y 또는 스크린샷으로 정확한 x좌표 확인, "편집"과 혼동 주의) 클릭.
3. 드롭다운에서 "폴더로 이동..."(단축키 표시 ⌘⇧G) 클릭.
4. 텍스트필드 자동 포커스됨 → `input chord cmd a --yes`(기존 내용 전체선택, 필드에 이전 경로 남아있을 수 있음) → `input text "<절대경로>" --yes` → 자동완성 드롭다운(경로 후보) 무시하고 바로 `input key return --yes`.
5. 즉시 해당 폴더로 이동+내용 전체 표시(리스트뷰 기준 실증, 컬럼뷰에서도 동일 작동 예상).

경로 표기법(둘 다 작동 확인):
- `~/` 홈 기준 상대경로(예: `~/workspace-egov/youtube-top/python-server/projects/<날짜폴더>`).
- 절대경로(`/Users/bumsuklee/...`)도 가능(미실증이나 표준 macOS 동작상 지원 확실).

컬럼뷰 클릭탐색 사용 시점(폴더로 이동이 안 통하는 예외적 경우만):
- 정확한 경로를 모르고 탐색(browse)해야 할 때만 컬럼뷰 사용.
- 컬럼뷰 로딩 지연 기준: 클릭 후 다음 컬럼이 **3초 이상** 안 뜨면 재클릭 반복하지 말고 2~3초 더 대기 후 재확인(대량 폴더[예: projects, 수십개 하위항목]는 로딩이 느릴 수 있음, 성급한 재클릭이 오히려 다른 항목 선택으로 이어질 위험) — 그래도 안 되면 "폴더로 이동"으로 전환.
- 파일선택 다이얼로그(NSOpenPanel) 내 "검색" 필드는 이전 세션의 필터(예: 파일종류 "media")가 잔류해 0건 오탐할 수 있음(a_1049~1057 관찰) — 검색 대신 "폴더로 이동" 우선 사용 권장.

자주 쓰는 프로젝트 루트 경로(kong-bot 작업 기준):
- `~/git/kong-bot` — kong-bot 저장소 루트.
- `~/workspace-egov/youtube-top/python-server/projects/` — CineBot 생성 영상 프로젝트(날짜별 하위폴더, 예: `20260819_2026-08-21_12간지_오늘의_운세_ko`).
- `~/workspace-egov/youtube-top/python-server/` — CineBot 백엔드 소스.

VERIFY:
- 이동 직후 스크린샷으로 창 제목(상단)+breadcrumb(하단, "Macintosh HD > 사용자 > ... > 대상폴더")가 목표 경로와 일치하는지 확인.
- NSOpenPanel(파일선택 시트)에서도 동일 절차 적용 가능(a_1060 YouTube 업로드 다이얼로그에서 실증).

LIMIT/OPEN:
- 절대경로(`/Users/...`) 표기 자체는 미실증(상대경로 `~/`만 실제 사용) — 필요시 재검증.
- kongtrol chord가 3키 조합(cmd+shift+g) 미지원인 근본 이유 불명 — 메뉴 경유가 현재 유일한 신뢰 가능 대안.
