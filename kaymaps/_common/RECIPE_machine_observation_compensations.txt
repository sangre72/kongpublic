     SPECIFIC, repeatable failure modes; each has a specific compensation. catalog them so they're
     engineered around, not re-discovered.

[1] PIXEL-PRECISION BLINDNESS
  problem: VLM-eye judges "where exactly is the outline" only coarsely(±tens of px). traced curves
    drift/invert vs the photo even when "looking at" it(M3 hood inverted+wrong length).
  fix: outline/edge/color-boundary = COMPUTABLE. extract contour deterministically(PIL edge-detect/
    threshold), map to viewport coords(affine from ref-plane corners), THEN click. eye's job shrinks to
    "did the point land on the line"(binary check = within VLM precision). M4 proved: near-exact overlay.

[2] NUMBERS-MATCH ≠ SHAPE-MATCH
  problem: width-at-height fractions matched ref exactly, yet cross-section stayed a round dome
    (bm34 incident). metrics sampled sparsely can all pass while the SHAPE between samples is wrong.
  fix: after any numeric fit, render and LOOK at the actual shape; claim fixed only when the change is
    visible in the render. metric=necessary, visual=sufficient.

[3] SMOOTHING MASKS GEOMETRY
  problem: subdiv/smooth-shading rounds away the base mesh's real form — judged the base wrong when
    the DISPLAY was the culprit(bm36: subdiv=2 dome; smooth:true hid flat facets even at subdiv=0).
  fix: inspect base mesh(subdiv=0, flat-shade) FIRST to see true geometry; add smoothing deliberately,
    per-object(smooth only genuinely-round parts: wheels; flat-shade paneled bodies).

[4] SINGLE-VIEW DELUSION
  problem: side-ortho silhouette diff hit 0.043 while the front view was still a round egg and 3/4
    looked like a beetle. one projection says nothing about the other two axes.
  fix: minimum verify set = front+side+top ortho + one 3/4 perspective, EVERY milestone. depth must be
    measured, not assumed(u_4207).

[5] FLATTERING-ANGLE BIAS
  problem: milestones rendered/judged from the one angle that looked best(hero-side), plateau went
    unnoticed(bm7≈bm8, bm34≈bm35 "visible change" claims).
  fix: fixed camera set per milestone(same angles every time) + diff against the PREVIOUS milestone's
    identical angle; "improved" requires a visible delta in at least one fixed view.

[6] COMPLEXITY MISCALIBRATION
  problem: judged a ~9k-tri single-mesh blob "close" to a subject whose real mesh = 113 parts/2.43M tris
    (~270x denser). resemblance is impossible at toy part-count; the judgment itself was the bug.
  fix: assume ANY real art/engineering subject = 100k+ polygons/objects. before claiming resemblance,
    state your part/poly count vs the subject's(or its reference mesh's) — that ratio IS the gap.

[7] DRAWING BLIND
  problem: generating geometry from computed numbers and only occasionally rendering = "안보고 그리기".
    wrongness accumulated invisibly for hours(entire blender script era).
  fix: eyes-on-result after EVERY operation(viewport screenshot per step in GUI work; render per change
    in scripted work). one op → look → next op. slow is correct.

[8] SEGMENT/CORNER CONFLATION
  problem: silhouettes were drawn as one continuous smooth curve across visible ANGLE BREAKS
    (hood→windshield, roof→liftgate), blurring the subject's structural corners(u_4233).
  fix: before drawing, classify every junction on the ref: smooth-tangent point vs corner point.
    corners = separate segments meeting at an angle; never smooth-join across a visible discontinuity.

[9] CAPABILITY≠LEGIBILITY OVERCLAIM
  problem: "ceiling broken, reads as paneled car" when the mesh HAD seams but the render showed nearly
    none(bm53). internal state was reported as visual truth.
  fix: report the two separately: (a) capability/mesh-state(what exists in data) (b) visual legibility
    (what a fresh render actually shows). claim (b) only from a fresh render viewed with own eyes.

[10] CONTEXT-IDENTITY BLINDNESS
  problem: searched for a button by scrolling an entirely WRONG SCREEN(raw-JSON debug tab) — the eye
    checked "is the element here" without first checking "is HERE the right place"(u_4167). same family:
    Finder row-position≠file-identity(u_4157), stale coords after view change.
  fix: verify screen/tab/breadcrumb identity BEFORE element search; identify targets by text/name not
    position; re-query coords after any view change.

[5b] SFS v2 fineness (a_4253, kong3d/scripts/shape_from_shading2.py): (a) sub-pixel edge via
  parabola-vertex fit on Laplacian peak per scanline(fractional y). (b) multi-scale: fine σ1.0(thin
  creases, red) + coarse σ4.0(panel boundaries, blue) — one scale blurs thin lines, two separates them.
  (c) adaptive local-window threshold(mean+k·std) + response FLOOR(k4.0/floor0.45 fine) — ★without floor
  it fires on paint micro-texture everywhere(over-detection); floor is essential on glossy paint. (d)
  gradient-direction field 8×12 cells(0-7=22.5° bins,-1 flat)=surface curvature orientation. (e)
  repeatability = MAD-robust residual of crease polyline vs quadratic fit(report px). LESSON: tighten
  the y-band to ONE feature before measuring repeatability — a wide band catches shut-line+char-line
  together and inflates residual(not a sub-pixel failure). overlay_2 red=thin creases blue=panels.
