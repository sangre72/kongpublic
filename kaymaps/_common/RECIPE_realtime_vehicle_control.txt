RECIPE: realtime_vehicle_control (★실시간 조작 게임 — 주행·조향·속도·각도 동시제어)
GATE: living doc, started 2026-09-12 (owner u_4646). Evidence = neal.fun not-a-robot L15 Parking.
REG: 방향키/키보드로 물체를 실시간 조작하는 모든 게임(주차·레이싱·비행·낚시·플랫포머 등).
WHY: 격자 선택형 퍼즐과 근본적으로 다른 문제. 퍼즐은 "어디를 누를까"(정답 탐색)지만,
  실시간 조작은 "얼마나 오래·무엇과 함께 누를까"(연속 제어). 클릭 좌표 레시피가 전혀 안 통한다.
CROSS-REF: _common/RECIPE_screen_decomposition.txt(D13 null-test), unknown_game_rule_discovery.txt.

===== V0. 먼저 입력 모델부터 판별하라 (3번의 측정으로 끝난다) =====
새 조작 게임을 만나면 아무것도 하기 전에 이 3가지를 각각 측정한다. 추측 금지.
 1. TAP 단발(`input key X --yes`) → 변화 있나?
 2. HOLD(`--hold 1500`) → 변화 있나? TAP과 크기가 다른가?
 3. 정지 상태에서 방향키 단독 → 변화 있나?
결과 해석:
 - TAP만으로 누적 이동 O → 이산(discrete) 이동. 격자 게임처럼 한 칸씩. 쉬움.
 - HOLD에서만 제대로 움직임 → 연속(analog) 제어. 아래 V1~V5 적용.
 - 방향키 단독 = 변화 없음 → ★차량형 모델: 움직이는 동안에만 방향이 바뀐다(실차와 동일).
   이 경우 조향은 반드시 전진과 **동시**여야 한다. 번갈아 주면 영원히 안 된다.
★EVIDENCE(L15): right 단독 --hold 2000 → 변화 0px. up --hold 1500 → 3313px. 이 비대칭 하나로
  "차량형"이 확정됐다. 이걸 안 재보고 번갈아 입력하느라 수십 동작을 낭비했다.

===== V1. 동시 입력 = 긴 키를 깔고 그 안에서 짧은 키를 친다 =====
kongtrol은 키 하나당 프로세스 하나다. 동시에 누르려면 백그라운드로 겹쳐야 한다:
```bash
( $KT input key right --hold 3000 --yes ) &   # 조향을 길게 깔고
sleep 0.3                                      # 먼저 눌린 상태를 만든 뒤
( $KT input key up    --hold 2200 --yes ) &   # 그 안에서 가속
wait
```
핵심은 **조향키를 먼저, 더 길게** 까는 것. 가속이 조향보다 먼저 끝나야 회전이 반영된다.
순차 실행(`A; B`)은 동시가 아니다 — 반드시 `&` + `wait`.

===== V2. 비율이 곧 조향각이다 =====
`조향 hold` ÷ `가속 hold` = 얼마나 급하게 꺾이는가.
 - 비율 1:1 → 완만한 곡선
 - 비율 4:1 이상(조향 4000 / 가속 1200) → 급선회. 좁은 통로에서 방향 틀 때
 - 비율 1:4 → 거의 직진. 미세 보정
각도를 "얼마나 눌렀나"가 아니라 **두 hold 값의 비율**로 설계하라. 이게 이 장르의 핵심 다이얼이다.

===== V3. 속도는 hold 길이, 위치는 속도×시간 =====
한 번에 멀리 보내지 말 것. 긴 hold 한 번(2000ms)보다 짧은 hold 여러 번(400ms×5)이
중간 관측을 허용해 훨씬 정확하다. 목표에 가까울수록 hold를 줄인다(2000 → 800 → 300 → 150).
★착지 정밀도가 필요한 순간(주차칸 진입·착륙)에는 hold 200ms 이하로 미세조정.

===== V4. 관성·드리프트를 먼저 측정하라 =====
차량형은 키를 떼도 즉시 멈추지 않고, 기체마다 한쪽으로 쏠리는 편향이 있을 수 있다.
 - 측정법: 직진(up)만 길게 주고 궤적을 본다. 똑바로 가는가, 한쪽으로 휘는가?
 - 휜다면 그 편향을 상수로 보고 **매 전진마다 반대 조향을 같이 깔아** 상쇄한다.
★EVIDENCE(L15): up 단독이면 항상 왼쪽으로 휘어 같은 차에 박혔다. 이 편향을 "내 조작 실수"로
  오해하고 계속 재시도한 게 실패 원인. 편향은 측정해서 보정하는 대상이지 극복하는 대상이 아니다.

===== V5. 목표는 "통과"가 아니라 "정지 상태" =====
주차·착륙·도킹류는 목표 지점을 지나가는 게 아니라 그 안에 들어가 **멈춰야** 클리어다.
 - 진입 각도를 먼저 만든다(칸과 나란히) → 그 다음 전진한다. 각도 없이 접근하면 절대 안 들어간다.
 - 옆에서 진입하는 구조(주차칸)라면, 칸 옆까지 이동 → 칸을 향해 90도 회전 → 전진 순서.
 - 진입 후 즉시 입력을 멈춰 정지시킨다(관성으로 지나치지 않게 hold를 짧게).

===== V6. 매 동작 후 관측, 그리고 null-test =====
실시간 게임은 스스로 애니메이션한다. "화면이 변했다 = 내 입력이 먹혔다"는 거짓이다.
반드시 무입력 대조군을 먼저 재고(D13), 변화의 **위치와 방향**으로 판정하라.
★EVIDENCE(L15): 무입력 1.5초에 3314px 변했다. 내가 "전진 성공"이라 보고한 3294px와 같은 수준이었다.

===== V7. 막히면 상태를 초기화하고 처음부터 =====
누적된 각도·위치가 꼬이면 보정보다 리셋이 싸다. 판 새로고침(↻) 후 V5 순서대로 다시.
단 리셋이 차 상태까지 되돌리는지 확인할 것(L15에서는 새로고침해도 차 위치가 유지됐다).

===== ★V8. 아는 물리를 "명령"으로 번역하는 표 (owner u_4647) =====
이론은 이미 안다. 부족한 건 그 이론과 키 입력 사이의 변환이다. 이 표가 그 변환이다.

| 물리 개념        | 게임에서의 관측            | 우리가 만지는 손잡이            | 실제 명령 |
|-----------------|--------------------------|-------------------------------|----------|
| 가속도 a        | 출발이 굼뜸/즉각적        | 가속키 hold 길이               | `up --hold 800` |
| 속도 v          | 이동 거리 = v×t           | hold 누적, 연타 간격           | 짧게 여러 번 |
| 관성/타력       | 키 떼도 더 감             | hold 종료 후 여유시간          | 목표 전에 미리 뗀다 |
| 조향각 δ        | 정지 중엔 안 변함         | 조향키를 가속과 **겹친** 시간   | `( right --hold 3000 ) & ( up --hold 2200 ) &` |
| 회전반경 R      | 급회전 vs 완만            | 조향:가속 **비율**             | 4:1=급, 1:4=미세 |
| 편향/드리프트   | 직진인데 한쪽으로 휨      | 매 전진에 반대조향 상시 부착    | 상수 보정값 |
| 정지            | 목표 초과(오버슈트)       | 접근할수록 hold 축소            | 2000→800→300→150 |

★번역 규칙 3가지:
 1. **연속량은 전부 "시간(ms)"으로 표현된다.** 속도·각도·거리 모두 hold 길이로만 조절 가능하다.
    "조금 더 오른쪽"은 좌표가 아니라 `--hold` 를 몇 백 ms 올리는 것이다.
 2. **동시성은 "겹친 시간"이다.** 두 물리량을 함께 걸려면 두 hold 구간이 겹쳐야 한다(V1).
    겹치지 않으면 물리적으로 별개 사건이라 합성되지 않는다.
 3. **비율이 형태를 만든다.** 절대값이 아니라 두 입력의 비가 궤적(직선/호/급선회)을 결정한다.

★제어 루프(이론의 PID를 우리 도구로 축약):
   목표와의 오차를 보고 → 다음 hold 를 정하고 → 한 번 실행하고 → 다시 관측한다.
   - 오차 크다 → 큰 hold(빠르게 접근)
   - 오차 작다 → 작은 hold(정밀 착지)
   - 오차가 부호를 바꿨다(지나쳤다) → hold 를 절반으로 줄이고 반대로
   이 "이분 탐색식 수렴"이 실시간 조작의 기본기다. 한 번에 맞히려 하지 말 것.

★디버깅 순서(안 될 때 이 순서로 의심):
   (1) 입력이 도달하나 → 효과가 명확한 곳에서 같은 키 시험(D13 교차검증)
   (2) 모델이 맞나 → V0 3측정 재실행(이산/연속/차량형)
   (3) 겹쳐 있나 → 순차 실행을 동시 실행으로 바꿨는지
   (4) 편향 보정했나 → V4
   (5) 각도 먼저 만들었나 → V5(각도 없이 접근하면 절대 안 들어감)
