★MPS i2v technical notes(2026-09-05 a_3803-3805): output resolution/aspect must be explicitly verified via ffprobe after EVERY generation(a width/height mismatch from intended landscape happened silently once) — don't trust node-config claims, measure actual output file dimensions. For batch-scale runs on this hardware, prefer lower resolution(e.g. 512x288, 32-aligned, 16:9) to manage render load across many scenes.
★i2v PROMPT-PHRASING lesson(2026-09-05 a_3806, u_3959 caught it): a descriptive gerund/noun-phrase motion-prompt("detective sweeping cloth with large hand motion") produces a STATIC HELD POSE, not actual motion — the model renders the described state, not the described action. FIX: write i2v motion-prompts as an ACTIVE SEQUENTIAL ACTION-VERB CHAIN("reaches down, grips edge, pulls back and away in one sweeping motion to uncover, arm swings up as cloth lifts off") — reach→grip→pull→lift→reveal style, not a single descriptive phrase. Apply this phrasing style to ALL scene motion-prompts from the start(scenario stage), not just as a reactive fix when a scene shows a static-hold problem.
★OBJECTIVE MOTION-VERIFICATION(2026-09-05 a_3806): don't rely on eyeballing a clip to judge "did it actually move" — compute first-vs-last-frame PSNR(ffmpeg or similar) per generated clip. Empirically, PSNR>~28dB = suspiciously static(near-identical first/last frame, held-pose failure), lower PSNR(~11-23dB range observed on genuinely-moving clips this run) = real motion present. Any clip flagging PSNR>28 should be treated as a static-hold failure and re-rendered with the action-verb-chain phrasing fix above — don't just report it as done because the file exists and plays.
★TWO-SIDED GATE(2026-09-05 a_3806 refinement): PSNR too LOW(~<9dB, esp. on flat-graphic/document scenes) can mean the OPPOSITE failure — over-morphing/unstable distortion(a document/diagram melting into streaky garbage from too-strong motion-strength on a low-detail flat image). Both extremes fail: PSNR>28(static) AND PSNR<~9 on flat-graphic content(unstable/melting) both need re-render. For flat/document/diagram scenes specifically, use CALMER motion(reduce shift_video/motion-strength, add "stable/clean/no-distortion" prompt cues) rather than the general action-verb-chain intensity used for character-action scenes.
