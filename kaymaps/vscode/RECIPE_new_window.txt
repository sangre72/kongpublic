RECIPE: new_window(VS Code, avoid touching other active window)
REG: a_980(2026-08-20)
WHY: 사용자가 활발히 쓰던 창(예: youtube-top)을 건드리지 않고 완전히 별도 창을 띄워야 하는 경우.
STEPS:
1. VS Code Dock 아이콘 클릭(1회)으로 기존 창 포커스 확보 — 이미 실행중이면 마지막 활성창이 뜸(건드리지 않아야 할 창일 수 있음, 주의).
2. `input chord cmd n` — VS Code에서는 Cmd+N이 "새 파일"이 아니라 Dock 우클릭 메뉴류(최근 프로젝트 목록+New Window 옵션)를 띄움(2026-08-20 실측, 일반적 새파일 단축키 아님 — 앱별 다를 수 있음, 매번 확인 필요).
3. 메뉴에서 "New Window" 클릭 — 좌표는 메뉴 노출된 화면 그대로 캡처해 육안 확인(a11y 미노출, dock메뉴는 별도 시스템 UI).
4. VERIFY: 새 창(Welcome 페이지, "Visual Studio Code / Editing evolved" 타이틀)이 별도 창으로 열림 + 기존 창(예: youtube-top)이 배경에 그대로 남아있는지 스크린샷으로 확인(가려짐=안전, 사라짐=문제).

★TITLEBAR-CHECK 개선(a_981): 화면상단 crop(예 -R0,50,1400,50)으로 타이틀바 확인하는 방법은 배경창(다른 VS Code 인스턴스)의 메뉴바/주소창이 항상 최상단에 남아있어 오판 유발 위험(2026-08-20 실사고: 새창이 실제 최전면인데도 crop방식은 배경 youtube-top 문자열을 계속 보여줌). ★대신 `see --a11y --compact --pid <PID> | grep "AXWindow"` 결과의 **첫 번째 항목**이 현재 최전면 활성창(accessibility API가 z-order 순 반환) — 이 방법이 훨씬 신뢰가능. 매 액션 후 이걸로 검증 권장.
