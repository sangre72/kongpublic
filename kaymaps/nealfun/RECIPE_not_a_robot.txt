[LVL 6] TYPE: known-game / tic-tac-toe (adversarial; opponent replies after every move)
VERB-PARSE: verb="Win at", object="Tic Tac Toe" -> unit of judgement = the BOARD containing 3 of MY marks in a line; done = that line exists. ★KNOWN GENRE (P0-PRIME-B): the entire game is known before probing — apply it, ¬rediscover it.

HOW TO PLAY: 3x3 grid, two marks (X and O). Players alternate. You claim ONE empty cell per turn by clicking it.
WIN CONDITION: three of YOUR OWN marks in a line — any row, any column, or either diagonal.
LOSS: the opponent achieves that first.
DRAW: all 9 cells filled, no line. ★A drawn board CANNOT be verified — press REFRESH for a new game. This is normal, ¬a failure.
RULES: cannot click an occupied cell (the click is silently ignored — re-read the board, ¬assume it registered). Turn passes to the opponent after each valid move. The mark you are assigned (X or O) is whatever the game gives you — READ it from the first move, ¬assume.

STRATEGY (minimum actions; this ordering never loses). Opening: take CENTRE if free, else a corner. Then each turn in strict priority:
 1. I have two in a line + third cell empty -> PLAY IT, WIN.
 2. Opponent has two in a line + third empty -> BLOCK.
 3. Create a FORK — one move giving me TWO separate two-in-a-rows at once.
 4. Block the opponent's fork.
 5. Centre -> opposite corner -> any corner -> any side.

★CAUTION (captcha-parody site): a level may be RIGGED/absurd (opponent cheats, cells move, extra cells appear). The classic rules above are the BASELINE used to DETECT deviation; if the board behaves abnormally, record the deviation as this level's real RULE and adapt. On this playthrough the board behaved as normal tic-tac-toe — no deviation observed.

SOLVE (the game that won): refresh to an EMPTY board -> corner r1c1 -> O replied r1c2 (¬centre) -> take CENTRE -> O blocked r3c3 -> r2c1 = FORK (threatens r2c1-r2c2-r2c3 AND r1c1-r2c1-r3c1) -> O could only block one, took r3c1 -> r2c3 completes the middle row -> Verify.

[LVL 15] UPDATE 2026-09-12 — permission restored, now blocked by a TOOL LIMITATION
After re-signing kongtrol and re-toggling Accessibility, input works again: `key up` visibly drives
the Waymo forward (verified by before/after diff and by the car climbing several rows).
★REMAINING BLOCKER: STEERING. `key right` / `key left` never rotate the car, at any repeat count,
with --human, or with right+up fired concurrently from two processes. Forward motion accumulates
from discrete taps, but rotation does not.
DIAGNOSIS: this is an analog-steering driving game — the wheel turns only while a key is HELD DOWN.
kongtrol `input key` emits discrete keydown+keyup pairs (see `input key --help`: "특수키 1회");
there is no hold/duration option. So sustained-input games are currently out of reach.
FIX NEEDED (tool-side, not game-side): add a hold option to kongtrol input key, e.g.
`--hold <ms>` that posts keyDown, sleeps, then keyUp (CGEventPost with separate down/up events).
That single feature would unlock this level and any other real-time/analog-control game.

fidelity limit. Next idea if revisited: emit repeated keydown events WITHOUT interleaved keyup
(auto-repeat emulation) rather than a single long press.
