RECIPE: combo_widget_and_run_button (ComfyUI 캔버스 콤보위젯 드롭다운 선택 + 실행버튼 클릭 — ★2026-08-26 확정)

WHY: 2026-08-26 Wan2.2 overnight-learning 세션에서 LoRA 콤보위젯("파일 미리 로드 안 됨" 오류) 수정+실행 트리거에 1시간+ 소요. 원인=좌표추측 반복+캔버스 확대율 오인. 확정법 기록.

★★★콤보위젯(드롭다운) 값 변경 확정법:
1. 노드를 화면 중앙으로 드래그(타이틀바 드래그)해서 모든 필드가 잘리지 않게 배치 — 스크롤된 상태에서 클릭하면 좌표가 다른 필드로 오배정됨(실사고: length필드 클릭한다고 생각했는데 실제 height필드였음).
2. 크롭 스크린샷(`screencapture -R0,150,2000,1000`)으로 필드별 정확한 y좌표를 표 형태로 재측정 — crop offset을 더해 원본좌표 환산(예: crop y=624 + offset 150 = 774).
3. 콤보필드 클릭 → 입력창 자동 오픈 → **필터 텍스트 입력**(예: "HIGH") → 후보 1개로 좁혀짐 → **Enter키로 확정**(클릭이 아니라 Enter가 안정적, 클릭은 좌표 오차로 실패 반복 관찰됨).
4. 확정 후 오류패널 개수 감소 확인(2개→1개→0개 식으로 즉시 반영됨, 새로고침 불필요).

★★★"실행" 버튼 vs 배치-카운터 스핀박스 구분(★실사고 — 같은 헤더 바에 있음, 혼동 매우 쉬움):
- 상단 실행바 구성: `[⠿드래그핸들][숫자 카운터 스핀박스][▶ 실행 버튼(파란색)][✕][N개 활성]`
- **카운터 스핀박스**(예: 좌표 1364,187 근방)를 클릭하면 배치 실행 횟수만 증가(1→2→3...) — 실제 실행은 트리거 안 됨. 여러 번 눌러도 "0개 활성"과 API `queue_running: []`이 계속 유지되는 게 증상.
- **진짜 실행 버튼**은 파란 배경의 "▶ 실행" 텍스트 그 자체 — 스핀박스보다 오른쪽(실측 좌표: 카운터=1364,187 / 실행버튼=1449,187, 약 85px 차이). 얼핏 봐도 같은 바 안이라 실수하기 쉬움.
- ★검증법(추측 금지): 클릭 후 반드시 `curl -s http://127.0.0.1:8188/queue | python3 -m json.tool` 로 `queue_running` 배열에 실제 프롬프트 JSON이 들어왔는지 확인. UI 표시("N개 활성")만 보고 판단하면 오배정된 카운터클릭도 착시로 "동작하는 것처럼" 보일 수 있음.

★★★브라우저 탭 in-memory 상태가 파일 값을 덮어쓰는 문제(2026-08-26 30분+ 소모):
- JSON 파일을 python으로 직접 편집(예: length=25, LoRA 파일명 수정) 해도, **이미 열려있는 브라우저 탭**은 그 변경을 반영 안 함(탭이 자체 in-memory 워크플로 상태를 유지, 파일 변경 감지 안 함).
- `Cmd+R`(새로고침)조차 SPA라 페이지 리로드 대신 다른 동작(텍스트 selectAll 등)으로 흡수될 수 있음 — 브라우저 새로고침 버튼(좌상단 원형 화살표 아이콘) 직접 클릭 필요.
- 새로고침해도 "변경사항 저장 안 될 수 있음" 확인창이 뜨며, **탭의 in-memory 상태(파일과 다른 stale 값)가 오히려 우선 적용**되는 역설적 현상 관찰됨 — 새로고침 후에도 옛날 값(length=81)이 다시 나타남.
- ★확정 해결책: 문제되는 탭을 완전히 닫고(X버튼→"나가기"로 변경사항 버림) 새 탭에서 워크플로를 처음부터 다시 열기. Chrome 전체 재시작(cmd+q)은 세션복원 기능 때문에 탭 상태를 그대로 되살려 효과 없음 — **탭 단위로 명시적으로 닫고 새로 열어야 함**.
- 참고: 파일시스템의 JSON은 편집대로 정확히 저장되고 있었음(mtime·내용 둘 다 실측 확인됨) — 혼란의 원인은 항상 "파일이 틀렸나"가 아니라 "브라우저가 그 파일을 안 읽고 있나"였음. 다음엔 파일 재확인보다 브라우저 탭 재확인을 먼저 의심할 것.

VERIFY:
- 콤보 확정: 오류패널 카운트 감소(즉시 반영, a11y 불필요, 스크린샷 육안 확인으로 충분).
- 실행 트리거: `curl queue`의 `queue_running` 비어있지 않음 = 진짜 성공. UI만으로 판단 금지.
- 파일-브라우저 동기화: python으로 JSON 재확인(mtime+실값) → 브라우저 표시와 다르면 탭 stale, 탭 닫고 재오픈.

LIMIT/OPEN:
- 정확한 필드별 y좌표는 노드 크기·확대율·스크롤 위치에 따라 매번 다름 — 위 크롭재측정 절차를 매번 반복해야 함(하드코딩 좌표 재사용 금지).

★★★★★2026-08-26 치명적 추가교훈: LoadImage 콤보(파일피커) ≠ LoRA 콤보(단순 텍스트리스트) — UI 동작 완전히 다름:
