RECIPE: minimax_h3_i2v (MiniMax H3 I2V via direct API submit — ★성공확정, 2026-08-26)
REG: http://127.0.0.1:8188 (ComfyUI 웹UI/API), macOS MPS. native ComfyUI-core support(no custom_node needed, comfy_extras/nodes_minimax_h3.py already ships w/ ComfyUI 0.33.0+).
WHY: Wan2.2로 배경/장면 프롬프트 반영 시도 하루종일 실패(흰배경 고정) — MiniMax H3로 전환해 해결. 단 gen시간은 Wan2.2보다 훨씬 느림(24분 vs 3분).

★★★필수 모델 3종(network-budget 큼, 총 ~30GB):
1. transformer(DiT): `models/diffusion_models/MiniMax-H3/MiniMax-H3-FL2VA-Pruned-Q3_K_M.gguf`(8.9GB, Abiray/MiniMax-H3-Pruned-GGUF repo — FL2VA=First-frame-to-Video, I2V용도와 일치)
2. text encoder: ★★★GGUF분할버전(main+mmproj) 사용 금지 — `comfy/sd.py`의 minimax 감지로직이 `visual.deepstack_merger_list`+`model.layers.49.self_attn.q_proj.weight` 두 키가 **동일 state_dict**에 있어야 인식하는데, GGUF_KREA-2 fork의 DualCLIPLoaderGGUF는 2파일을 별도 dict로 로드해 병합 안 됨(런타임에러: "the JSON object must be str, bytes or bytearray, not NoneType"). **정답=공식 단일파일**: `models/text_encoders/qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`(15.7GB, Comfy-Org/MiniMax-H3 repo) — 표준 CLIPLoader로 로드, GGUF 로더 불필요. 크기도 더 작음(gguf분할본 19.76+1.14=20.9GB보다 작음) — 처음부터 이걸로 시작할 것.
3. VAE: `models/vae/minimax_h3_video_vae_fp16.safetensors`(5.2GB, Comfy-Org/MiniMax-H3 repo)

★API 포맷 노드 그래프(캔버스UI 없이 직접 submit 성공):
- `UnetLoaderGGUF`(unet_name=위 1번 파일)
- `CLIPLoader`(clip_name=위 2번 파일, **type="minimax"**★필수)
- `VAELoader`(vae_name=위 3번 파일)
- `LoadImage`(소스 이미지)
- `MiniMaxH3ImageToVideo`(clip, vae, prompt, width, height, length, first_frame=LoadImage출력) — length는 **17*k+5 그리드**(5,22,39,56,73,90,107,124...)로 스냅됨, 임의값 불가. positive conditioning + latent 동시출력.
- `MiniMaxH3SigmaShift`(model, shift_video=12.0 기본, shift_audio=3.0 기본) — UnetLoaderGGUF 출력을 감싸 KSampler에 연결.
- `KSampler`(model=SigmaShift출력, positive/negative=MiniMaxH3ImageToVideo의 conditioning출력 그대로 재사용해도 동작함, latent_image=같은 노드의 latent출력, steps=20 기본, cfg=4.0, sampler=euler, scheduler=simple)
- `VAEDecode` → `CreateVideo`(fps=24, MiniMax H3는 24fps 고정) → `SaveVideo`(★format 필드 필수, 안 넣으면 "missing 1 required positional argument: format" 에러 — CreateVideo 아니라 SaveVideo 쪽에 넣어야 함, 헷갈리기 쉬움).

VERIFY:
- API 응답 `node_errors`가 빈 딕셔너리인지 확인.
- 완료로그 `Prompt executed in HH:MM:SS`.
- ffprobe로 width/height/fps/duration 실측(length=22프레임@24fps → duration≈0.92s로 정확히 일치 확인됨).
- ★배경 반영 여부는 첫프레임이 아니라 **끝프레임**으로 확인할 것(2026-08-26 실측: 첫프레임=원본이미지 그대로 흰배경, 끝프레임=프롬프트 배경(고딕 성 대전당) 완전 반영 — 애니메이션 특성상 배경 전환/카메라무브가 뒷부분에 나타남).

★★★터보 LoRA(2026-08-26 확정, 필수 적용 권장): 기본 20스텝은 22프레임에 24분(1436초) 소요 — 원인은 스텝수(step-count) 자체, MPS/메모리 문제 아님(둘 다 실측확인됨). `lightx2v/Minimax-h3-Turbo`(HF repo, ★ModelTC 아님 — 검색시 흔히 혼동됨) 8-step distillation LoRA(`minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors`, 1.96GB, comfyui-suffix버전 사용) 적용시 467.79초(7:48)로 단축(3.07배speedup, 스텝비율 20/8=2.5배와 근접). 품질 저하 육안상 없음(배경/캐릭터 둘다 20스텝과 동등, side-by-side 비교완료).
적용법: `LoraLoaderModelOnly`노드를 UnetLoaderGGUF 출력과 MiniMaxH3SigmaShift 사이에 삽입(model 체인에 끼워넣기), steps=8로 변경. 4-step 변형(`minimax_h3_fl2v_turbo_4step_v1.1_768p_comfyui_bf16.safetensors`)도 존재 — 더 빠른 속도 필요시 시도해볼 만하나 미검증.
★이후 모든 MiniMax H3 생성은 이 터보로라 기본 적용 권장(20스텝 원본은 특별한 이유 없으면 안 씀).
