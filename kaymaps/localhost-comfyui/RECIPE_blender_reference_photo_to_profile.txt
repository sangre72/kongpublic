[GATE] VERIFIED 2026-09-06 a_3834 (worker1) — Model Y traced-profile via this method, visibly more accurate than guessed proportions (ar_3833).
[TOPIC] kong-blender-wrap: model a real-world object from REFERENCE PHOTOS → silhouette → `profile` op (single continuous extruded mesh). Reusable for ANY subject (vehicle, bottle, tool, furniture — anything with a readable side silhouette).
[REG] kong-blender-wrap/ (kbwrap.py + scripts/runner.py `profile` op). Any "make it look like <real thing>" modeling task.

[WHY]
- Guessing proportions from text dimensions (ar_3831/3832/3833) does NOT resemble the real object — it reads as a generic shape. The silhouette must come from an actual reference.
- The `profile` op (a_3833) is the right technique (one continuous mesh, no boolean seam) but is only as good as the profile fed to it. Garbage-in = generic-shape-out.

[STEPS — standing workflow]
1. GATHER MULTIPLE REFERENCES (not one):
   - SIDE elevation = primary (this is what `profile` consumes — the outline).
   - FRONT + REAR = for detail-op placement (light-bar shape/height, badge, grille, light-strip proportions).
   - TOP (if relevant) = for width/taper cues.
   - Sources that actually download headless: Wikimedia Commons via `curl -sL "https://commons.wikimedia.org/wiki/Special:FilePath/<File Name>.jpg"` (reliable, licensed). Stock-PNG sites (stickpng/purepng/netcarshow) mostly 403 headless — don't waste attempts. Orthographic "blueprint" line-drawings are IDEAL for side-elevation if obtainable.
2. OBTAIN A CLEAN SIDE VIEW: prefer a true orthographic/side-elevation. If only an angled (¾) photo is available, note the foreshortening and correct proportions against the object's KNOWN real dimensions (e.g. wheelbase/length ratio) — don't trace the foreshortened pixels literally.
3. EXTRACT THE SILHOUETTE — method by what's available:
   a. Transparent-PNG side view → the alpha channel IS the silhouette; auto-trace the alpha boundary (PIL: sample the outer alpha contour at N x-intervals → [x,z] list). MOST accurate when a clean transparent side exists.
   b. Clean side-elevation on plain background → color-key/threshold the car vs background, trace the boundary.
   c. Cluttered/angled photo (common reality) → ★VISION-TRACE: the worker (has image-view) reads the image and hand-estimates [x,z] silhouette points at even intervals along the length, faithful to the REAL shape (hood dip, A-pillar rake, roof plateau, fastback slope, tail height, overhangs). This is legitimate + accurate — the worker IS the image-analysis tool. Honest-label it "vision-traced from reference", NOT "auto-extracted".
   → normalize to the profile op's frame: x = length (front +X), z = height, CCW outline, ground line last-two points across the bottom.
4. FEED TO `profile` op: {op:'profile', name, width (from front/top ref), profile:[[x,z]...], bevel, subdivide:2, smooth:true, material...}. → one continuous smooth body.
5. PLACE DETAILS against front/rear refs (not guessed): light-bar (emissive thin box at the ref'd height), wheels (arch centers read off the side ref, x-positions = wheelbase), cladding, sills.
6. ITERATE: render side-elevation view (camera straight -Y) → compare to the reference silhouette feature-by-feature (roof peak position, fastback angle, overhang lengths) → adjust [x,z] points → repeat until it matches. Then render ¾ hero + animate.

[VERIFY]
- Render a PURE SIDE view (camera on -Y axis, look_at centered) and compare silhouette directly to the reference side image — this is the honest test, not just a flattering ¾ angle.
- Read-tool view every iteration (mandatory visual QA, per project discipline).
- Honest verdict: state which specific reference features matched and which didn't; don't declare "exact" from a good ¾ angle alone.

REAL cars need ~18-20 profile points with DISTINCT segments: short nose → hood → hard windshield-rake transition → forward-of-center roof PEAK → long gentle roof taper → rear glass → tail → high LEVEL beltline. Straight-ish runs joined by short curves, NOT one continuous dome.
- Verify orientation early: front = +X in the op; render a pure-side and check the roof peak is FORWARD (matches ref), flip points if mirrored.
- Add a dark GREENHOUSE band (thin dark cube along the beltline, both sides) — sells the "long glass area" cue that the body-only silhouette can't.
- Correct the description against the actual photo, don't trust a text summary blindly: e.g. MY hood is SHORT (cab-forward EV), not "long flat" — the peak-forward + long-tail is the real signature.
- ITERATE against the ref image feature-by-feature (peak x-position, tail height, overhang lengths, beltline level) — took 4 profile revisions (myo1→myo4) to match.

[WHEEL ROLLING-AXIS (a_3836 — CORRECTED, supersedes ar_3830's wrong "X")]
- wheel mount = `add cylinder rotation:[90,0,0] scale:[1,1,0.3]` → correct upright disc, flat faces along car width, sits on road. (verified: side-cam frame0 = proper round wheel.)
- ROLLING SPIN axis = ★**Y** (NOT X, NOT Z). Empirically verified w/ a rim-marker test cube: X=coin-flip (disc tips out of plane, the reported "sideways sunk disc" bug), Z=yaw/steer, Y=clean roll (disc stays upright, marker travels around rim). ar_3830 concluded "X" — that was WRONG/regressed. Use axis="Y" for `spin` on wheels.
- diagnostic method (reusable): group wheel + a small offset marker cube, spin 1 turn each axis over ~12f, extract last frame, Read-view which axis rolls the marker around the rim while keeping the disc face toward a side camera.
- ★SPOKE orientation (a_3843 — else a false "axle bar" appears): wheel disc-axle = Y. spokes must RADIATE in the wheel FACE plane (X-Z): spoke cube long-axis = X (scale[0.42,0.05,0.05]), rotation[0,k*72,0] (spin about the Y axle). ✗ do NOT make the spoke long on Z + rotate about X — that points spokes INWARD along Y (toward car center), and mirrored L+R the two inward sets read as one bar/shaft spanning between the wheels (looks like an exposed toy axle). place spokes at the wheel's OUTER face (y just outboard of the rim).

[HARD-SURFACE DETAIL WORKFLOW (a_3837 — 2nd reusable technique, layers ON TOP of the profile silhouette)]
profile op = overall SILHOUETTE. hard-surface detail = panel-lines + small parts on top. ops:
- `inset` {target, select_dir:[x,y,z] (face-normal filter), z_range:[lo,hi] band, thickness, depth (neg=recess)} — bmesh face-inset for door-seams / panel recesses / recessed light-lenses (inset the light box's outward face). select faces by normal-direction + height-band, no manual selection.
- `mirror` {target, axis, apply} — mirror modifier about WORLD CENTER (auto kbw_mirror_pivot empty at origin, NOT the object's own origin — so an off-center part at +y reflects to -y). MODEL ONCE + mirror: wheels/handles/side-mirrors/cladding modeled on +y side, mirrored → perfect symmetry, half the work. ★NOTE: `apply:true` bakes L+R into ONE mesh under the same name → for a WHEEL that's fine (spin the merged mesh about Y = both halves roll together). If you need to animate L and R independently, use apply:false or model separately.
- non-destructive modifiers: `modify subdivide/bevel` already add persistent modifiers (not baked) — base mesh stays editable, restack/re-render without rebuild.
- small parts = cube/cylinder primitives with scale[x,y,z]: door handles (thin flush bars), side-mirror housings (small cubes on A-pillar), hubcaps (smaller lighter cylinder on the wheel outer face), char-lines (very thin dark cubes along the body), lower fascia/bumper cladding (black cubes). place on +y, mirror.
- 2025-refresh light lenses: DRL = thin full-width emissive strip; headlamps = separate small boxes with `inset` recess on the outward face (lens depth, not a flat rect); rear = full-width emissive bar + inset.
verified a_3837: Model Y rebuilt with door-seams(inset), handles+mirrors+hubcaps+cladding(mirror), 2025 DRL/rear lenses → visibly more detailed than flat-color version, wheels still roll (axis Y). 2 iterations (myd1→myd2).

[TARGET-IMAGE MATCHING + MULTI-REF (a_3838/3839 — iterate toward a specific photo)]
- Use MULTIPLE references, weight CLEAN studio shots > motion-blur driving shots for proportions. Verify each yourself (orch's read can be wrong: e.g. "no pillar breaks" was a blur artifact; clean shots showed a clear C-pillar).
- MATCH THE CAMERA ANGLE to the target before judging: front-3/4 target → camera at +X,+Y; rear-3/4 studio → camera at -X,+Y. Comparing a rear-view render to a front-view target = false mismatch.
- Greenhouse with PILLARS (not one band): split the glass into per-pane dark cubes (front-door / rear-door / rear-quarter) with body-color GAPS between = B/C pillars. Single continuous band reads wrong for most cars.
- FULL-PERIMETER lower cladding (not just wheel-arches): one long rocker strip (mirror) + arch flares + front/rear bumper-corner cubes, all near-black. Strong visual cue on SUVs/EVs.
- 5-spoke wheel: tire cylinder + lighter rim cylinder + 5 thin spoke cubes at rotation k*72° (radial). Size the tire so it sits FLUSH in the arch (tight gap) — proud/gapped wheels read toy-like. Tuck inward (small y) so they don't stick past the body sides.
- SUV vs sedan height: raise the roof/cabin profile z-points (+0.10) for a taller SUV greenhouse; the profile op controls stance.
- 2025 front: full-width emissive DRL strip + round emissive fog cylinders low in corners (rotation[0,90,0] to face forward) + black lower fascia.
- CHECKPOINT DISCIPLINE: save numbered iterations (myt1,myt2...) never overwrite-only — keeps a comparable progress history.

[AERO SMOOTH SURFACE — width-varying LOFT (a_3841, fixes constant-width boxiness)]
- ROOT CAUSE of "boxy" (confirmed by test, not guessed): the `profile` op = constant-width extrude → flat vertical side-panels + hard edges at the extrude boundary. subdiv-level alone does NOT fix it (tested subdiv=4: profile-curve edges soften but SIDES stay dead-flat slabs — no width geometry to smooth). A real car curves in BOTH side-profile AND plan (width) simultaneously.
- FIX = `loft` op: build ONE body by lofting between WIDTH-VARYING cross-sections. op:{name, sections:[{x, section:[[y,z],...]}...], subdivide, smooth, color...}. each section = a closed Y-Z ring at that x (SAME vert-count + consistent ordering across all sections); bmesh bridges consecutive rings into quads + caps ends → doubly-curved solid.
- generating sections: reuse the side-profile for top/bottom z at each x (interp), + a plan-view half-width(x) curve (parabolic fullness, taper nose+tail) → build a rounded-RECTANGLE ring per x (flat-ish narrower roof, crisp beltline at widest, near-vertical door sides, rounded rocker). NOT a superellipse (too blobby → river-stone, loses roofline).
- tuning lessons: DENSE sections through the greenhouse (hold the roof shape) — ~18 sections; keep subdiv LOW (1) so structure survives (subdiv 2-3 over-smooths the roofline into a mound); put the widest y at the beltline z to get a crisp shoulder/character line automatically.
- STATUS a_3841: loft op built + verified producing smooth aero doubly-curved surface w/ emerging beltline crease (myt9→myt10) — the flat-slab boxiness is GONE. still iterating section-shapes for crisper roofline/greenhouse definition (soft roof remains). loft = the correct tool, replaces profile for the body when aero-smoothness matters (profile still fine for quick/blocky).

[LIMIT/OPEN]
- Auto-alpha-trace (3a) needs a clean transparent side PNG; those are often paywalled. Vision-trace (3c) is the reliable fallback and was used for Model Y (a_3834) — good result, just be honest it's vision-estimated not pixel-perfect.
- The `profile` op does a symmetric extrude (constant width along length). Real cars taper in width (narrower roof, wider haunches) — not captured by a single side-profile. For width-variation would need a loft/multi-section op (not built; flag if needed).
- Window glass, door lines, badges = separate detail ops (thin dark insets), not part of the silhouette profile.
