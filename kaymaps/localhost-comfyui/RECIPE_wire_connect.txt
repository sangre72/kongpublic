RECIPE: wire_connect (ComfyUI 캔버스 소켓-소켓 연결 — ★★★최종결론: JSON 직접 링크추가가 최우선, 캔버스drag는 2순위)
REG: http://127.0.0.1:8188 (ComfyUI 웹UI, 캔버스 WebGL 그래프 영역)
WHY: FLUX 워크플로 구성 중(a_2197/2200/2205) 최초 시도는 정밀도·재현성 문제로 포기, RECIPE_workflow_json_load.txt(JSON 불러오기)로 우회했었음. 그러나 로드한 blueprint에 출력노드가 없거나(LTX-2.3, a_2223~2248 / Wan2.2, a_2264~2294) 이미지입력 연결이 비어있는 경우가 있어 결국 캔버스 내 소켓연결이 다시 필요해졌고, 2026-08-25 여러 차례 시행착오 끝에 방법을 확정.

★★★★2026-08-25 최종결론(Wan2.2 세션 갱신): 캔버스 drag(아래 방법1)는 1시간+ 시도해도 실패할 수 있음(노드가 자동스냅되며 소켓이 계속 가려지는 문제 반복) — **막히면 즉시 JSON에 링크를 직접 추가하는 방식(방법0)으로 전환할 것**. 이미 노드 교체(GGUF전환 등)를 JSON 직접편집으로 여러 번 성공시킨 전례가 있으므로 같은 방식이 훨씬 빠르고 확실함.

★★★방법0(최우선, 성공확정): JSON 파일에 링크 직접 추가
1. 워크플로 JSON을 python으로 로드, `links` 배열 구조 확인(형식: `[link_id, 출력노드id, 출력slot, 입력노드id, 입력slot, 타입문자열]`).
2. 연결하려는 두 노드(출력측/입력측)의 id+slot 인덱스 확인(노드의 `outputs`/`inputs` 배열에서 슬롯 순서 파악).
3. `links` 배열에 새 항목 추가(link id는 `last_link_id`+1) + 양쪽 노드의 참조필드 갱신(`inputs[slot].link`=신규id, `outputs[slot].links` 배열에 신규id 추가) + `last_link_id` 값도 갱신.
4. 링크 무결성 전수검사(모든 링크가 실존하는 노드id/slot만 참조하는지) 후 저장.
5. 브라우저 새로고침 → 오류패널에서 해당 연결 오류 사라졌는지 확인.
- ★주의: 브라우저에서 캔버스 위 노드를 새로 배치("비디오 저장" 등)했다면, JSON 편집 전에 반드시 "그래프→저장"으로 먼저 파일에 반영해야 함 — 안 그러면 links 배열이 텅 비어있어 편집 대상 자체가 없음(Wan2.2 세션에서 실제로 이 함정에 걸렸음).

★★2026-08-25 성공 확정 방법(방법1, 캔버스 drag — 방법0 실패시 또는 간단한 경우에만):
1. **노드 겹침 금지**: 두 노드(연결할 소켓을 가진)가 화면상 겹쳐있으면 소켓 원 자체가 가려져서 클릭이 거의 항상 "노드 이동"으로 오인식됨 — 반드시 완전히 분리된 상태로 배치.
2. **좌표 정밀도 확보**: Read 도구의 표시좌표(2000x1293, 원본 대비 배율 2.06)는 3~5px 오차가 누적되어 반복 실패의 원인이 됨. `screencapture -R <소켓근처 작은영역>` + `sips`로 정확한 물리픽셀 크기를 확인하는 초정밀 크롭 방식이 훨씬 정확.
3. **근접 재배치 트릭**: 정확한 좌표를 못 찾겠으면, 오히려 두 소켓을 서로 매우 가깝게(수백px 이내) 재배치한 뒤 짧은 거리로 drag하는 게 성공률이 훨씬 높음 — 거리가 멀면 시작점·끝점 둘 다 고정밀이어야 하지만, 근접시키면 오차 허용범위가 커짐. (의도치 않은 "노드 이동" 결과가 오히려 유용한 재배치로 이어지는 경우가 많았음 — 실패해도 당황하지 말고 그 결과 위치에서 다시 좌표 재확인.)
4. **성공 신호 활용**: drag 시작점이 정확한 소켓이면 ComfyUI가 "노드 추천" 팝업(입력타입 필터)을 띄움 — 이 팝업이 뜨면 시작점은 맞았다는 뜻, 도착점만 미세조정하면 됨. 연결 성공시 소켓 색이 흰색→초록(또는 해당 타입색)으로 변하고, 두 소켓 사이 색깔 곡선(연결선)이 그려짐 — 스크린샷으로 육안 확인.
5. **검증**: "실행" 버튼 클릭시 에러 메시지 변화로 판단 가능(예: "출력이 없습니다" → "필수 입력 누락: input" → 에러 사라짐 순으로 단계적 해소 확인).

시도했으나 불필요/불가능으로 판명된 것:
- a11y 헤더좌표 기준 상대offset 계산: ★구조적 불가능. a11y가 제공하는 헤더 좌표는 캔버스(WebGL) 내부가 아니라 우측 별도 속성패널(DOM레이어) 좌표임 — 캔버스 내부 노드의 실제 화면좌표는 a11y 트리에 전혀 노출 안 됨.
- 노드 제거(우클릭 "제거")는 "캔버스에서 노드찾기"→중앙좌표 우클릭 패턴으로 가능하나 재현성 낮음(줌/팬 상태에 따라 중앙좌표가 매번 미세하게 다름).

VERIFY: 연결선(색깔 곡선) 스크린샷 확인 → 소켓 색상변화 확인 → 실행버튼 클릭시 관련 에러 메시지 해소 확인.
