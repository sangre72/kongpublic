RECIPE: save_as_dialog(krita, macOS native panel)
REG: a_974(2026-08-19)
WHY: Cmd+S 트리거된 macOS 네이티브 "다른 이름으로 저장" 패널은 Krita PID로 a11y 조회 안됨(별도 sandbox savepanel 프로세스) — 좌표는 매번 화면 전체캡처로 육안 확인 필요.
STEPS(★2026-08-20 a_975 갱신 — File메뉴 경유가 더 안정적):
1. ★Cmd+S 대신 **파일(File) 메뉴 → "다른 이름으로 저장..."** 클릭 경유 권장(메뉴바 "파일" 좌표는 a11y로 확인, 보통 118,20). 이 경로는 Save As 필드가 기존 파일명으로 미리 채워지고 전체선택된 상태로 열림 — 빈 필드보다 안정적.
2. 필드가 이미 전체선택 상태면 바로 `input text "문자열"`(한글 포함) 입력 — ★이번엔 정상 작동 확인됨(TRIAL-COUNT: Cmd+V 붙여넣기 2회 실패 후 input text로 전환해 성공, GATE 규칙 실증사례). 필드가 선택 안 된 상태면 먼저 클릭(좌표는 매번 화면 전체캡처로 확인, a11y 미제공)+Cmd+A로 전체선택 후 text 입력.
3. Save 버튼 클릭이 간헐적으로 안 먹을 수 있음(1회 클릭 후 다이얼로그 안 닫히면) → ★Enter(`input key return`)로 확정 시도(2026-08-20 확인: Save버튼 클릭 실패 후 Enter로 정상 저장됨).
4. (구버전 이슈, 참고용) Cmd+S로 새로 여는 빈 상태 다이얼로그에서는 `input text`가 한글자모변환 등 불안정했던 사례 있음(2026-08-19) — File메뉴 경유가 이 문제를 회피하는 것으로 보임.
VERIFY: 타이틀바가 "[저장되지 않음]"→"<파일명>.kra"로 변경 + 하단 상태바에 "<파일명>.kra 저장 완료" 텍스트 노출. `ls ~/Pictures/*.kra`로 실제 파일 존재+최신 mtime 확인.
