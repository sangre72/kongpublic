RECIPE: regular_video_upload_with_thumbnail (일반영상 업로드, 쇼츠 아님 — 제목+썸네일+해시태그+예약)
REG: a_2087(2026-08-23), ar_2087에서 실증. localhost:youtube studio.
WHY: 기존 RECIPE_scheduled_upload_VERIFIED.txt는 쇼츠(세로형) 업로드 기준. 일반영상(가로형/긴 영상)은 UI 레이아웃이 미묘하게 달라(예약 라디오 좌표 등) 별도 기록 필요. 또한 썸네일 이미지 적용은 쇼츠 레시피에 없던 신규 절차.
REF: [[RECIPE_scheduled_upload_VERIFIED]](같은 디렉토리) — 공통 절차(만들기→동영상업로드→드롭존 드래그)는 동일, 본 레시피는 차이점만 기록.

STEPS:
1. 채널 전환 필요시: [[RECIPE_channel_switch]] 절차 선행.
2. 만들기@(1884,158) 클릭 → "동영상 업로드" 메뉴 클릭(쇼츠와 동일) → 드롭존에 Finder 원본영상 파일 drag(input drag, --human) 업로드.
3. ★영상이 세로형 종횡비 아니면 자동으로 "일반영상"으로 처리됨(쇼츠 아님) — 별도 설정 불필요, 업로드된 파일 형태로 자동 판별.
4. 제목/설명 입력(cmd+a+text, 쇼츠와 동일 방식). 설명란에 해시태그 포함 가능.

5. ★썸네일 적용(신규 절차, 쇼츠 레시피엔 없음):
   - 썸네일 업로드 영역 a11y로 위치 확인 후 클릭.
   - ★Finder→Chrome 크로스앱 drag가 실패하는 경우 있음(Chrome이 백그라운드로 전환돼 Finder 내부에서만 드래그 처리됨, 2회 시도 모두 실패 사례 있음) → 대안: "파일 업로드" 버튼 클릭 → NSOpenPanel 오픈.
   - ★NSOpenPanel 내에서도 파일 좌표 클릭이 스크롤위치 불일치로 신뢰 안 될 수 있음 → ★확실한 방법: NSOpenPanel 검색창에 파일명 일부(예: 타임스탬프 부분 "03_10_36")를 input text로 입력 → 검색결과 1건으로 좁혀짐 → 그 결과 클릭 → "열기".
   - ★주의: 소스 이미지 파일이 지시서 작성 시점 경로(예: ~/Downloads)에서 실제 착수 시점엔 이동해있을 수 있음(사용자가 정리했거나 다른 프로세스가 이동) — 작업 착수 직전 반드시 `ls -la <경로>` 재확인, 없으면 `find`로 재탐색.

6. 다음×3(세부정보→동영상요소→검토→공개상태, 쇼츠와 동일).
7. 공개상태에서 "예약" 라디오 클릭: ★좌표가 쇼츠(@606,700)와 다름 — 일반영상 업로드 UI는 @(606,732) 근처(레이아웃 차이, 매번 a11y로 재확인 권장 — 고정좌표 맹신 금지).
8. 버튼 텍스트 "게시"→"예약" 전환 확인 → 예약버튼@(1430,1247) 클릭.
9. "동영상 예약됨" 다이얼로그에서 URL 추출(a11y grep), 스크린샷 촬영 → notify_telegram.py 등으로 전송(유저 명시요구시).
10. 닫기(쇼츠 레시피와 동일하게 "닫기" 버튼 사용, "저장 후 닫기"는 좀비 다이얼로그 유발 가능성 — 사용 금지).

VERIFY:
- 예약 다이얼로그의 실제 URL 확보로 완료 확정(UI 텍스트만으로 판단 금지).
- 썸네일 미리보기에 지정 이미지가 실제 반영됐는지 스크린샷 육안 확인.

LIMIT/OPEN:
