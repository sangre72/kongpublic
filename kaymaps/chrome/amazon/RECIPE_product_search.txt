★★★ STANDING STRATEGY: SPEC-DRIVEN FILTER FALLBACK(a_2922, 2026-08-30) ★★★

GENERAL(not SSD-specific) — apply whenever keyword-search hits the `k=`-param rendering bug(empty main-results-grid, per above) for ANY product type, not just storage hardware.

WHEN TO USE: keyword search(`amazon.com/s?k=<query>`) returns 0 `AXButton "장바구니에 추가"` in the main results area, AND no recommendation-carousel fallback is present(or carousel exists but you need the EXACT model, not just "something similar"). Don't retry the same broken keyword search repeatedly — switch strategy immediately once the empty-grid symptom is confirmed(1 clean a11y-dump check is enough, no need for multiple retries).

PROCEDURE:
1. **Identify real specs**(if not already known precisely): WebSearch the product externally(e.g. "Samsung 990 Pro SSD specs" or "<product> official specifications") — get concrete identifying details: brand, capacity/size, interface/connector type, series/model name, category. This must be a REAL lookup, not guessed/assumed from training data — product lineups change(cf a_2916-2918's 970-Pro-discontinued lesson).
2. **Navigate to the category** via hamburger-menu(`AXButton "모든 카테고리 메뉴 열기"` → drill down per RECIPE_category_navigation.txt's department→leaf-category pattern). This uses the search/nav UI legitimately — NOT the URL-bar shortcut(still respects the u_2966 mandatory rule, since you reach the destination via real menu clicks, just skip TEXT-TYPING the model name).
3. **Use the LEFT-SIDE FILTER PANEL** to narrow down: brand checkbox(`AXCheckBox`/`AXLink "<Brand> 필터를 적용하여 결과 좁히기"`), capacity/storage-size checkbox, interface-type checkbox, price-range, etc — A11Y-QUERY THE ACTUAL FILTER OPTIONS PRESENT on the page each time(`see --a11y --compact | grep -iE "필터를 적용"`), don't assume a fixed filter list exists across categories — filter options vary by department.
4. **Verify**: resulting URL should show `rh=n%3A<node>%2Cp_XXX%3A<facet-id>`(no `k=` param) — this confirms you're on the safe(non-bugged) path. Check `AXButton "장바구니에 추가"` count via a11y to confirm real products rendered.
5. If still too many results to pin the EXACT model(e.g. filters alone don't isolate one SKU), scan the rendered `AXLink` product-title text for the specific model name from step 1's spec-lookup — click that one directly, rather than typing it into search.

WHY THIS WORKS: confirmed root cause(above) is that `k=`(text-keyword) params in the results URL trigger the empty-grid bug; `rh=`/`p_XXX=`(category-node/facet-id) params do not. Filter-panel clicks only ever produce `rh=`/`p_XXX=` URLs, never `k=` — structurally immune to this specific bug class.
