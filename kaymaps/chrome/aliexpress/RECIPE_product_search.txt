★★CRITICAL(a_2892, real incident): price_asc sort does NOT filter by product-relevance/tier — it sorts ALL keyword-matched results(incl loose/substring/bundle-title matches) by price. A search for "Logitech MX Anywhere" returned genuine MX-Anywhere-line listings MIXED with completely different product lines(e.g. a "G102 시리즈" bundle-listing that just happened to mention "MX Anywhere 3S" as one SKU among many in its own title) — sort-then-blind-pick-#1(cheapest) picked the OFF-TARGET bundle-listing(₩5,417) instead of a genuine MX Anywhere product(cheapest-genuine was actually ₩18,443, several sort-positions lower).
  ★MANDATORY: after price-sort, DO NOT blind-trust position #1 — read/verify each candidate's actual TITLE(`AXLink`/`AXHeading` text) against the target product-line before selecting. Only pick past candidates whose title genuinely names the target product(not just contains it as a passing-mention/cross-sell substring).

★★NEW UI PATTERN(a_2893, real incident): SOME listings(often "알뜰마트"-tagged) route on click to a SUB-STOREFRONT HUB PAGE(URL pattern `aliexpress.com/ssr/300000512/kr2024update?...productIds=...`) instead of a normal `/item/<id>.html` product-detail page. This hub page:
  - shows a DIFFERENT mini-cart panel(separate cart-state from the main site's cart, initially "장바구니가 비었습니다"/empty) — NOT the same cart you've been adding to via normal /item/ pages.
  - mixes in unrelated cross-sell products(e.g. searched for a ladle, hub page shows random mice/electronics too).
  - the target item's title/name is often just `AXStaticText`/`AXGroup`(NOT a clickable `AXLink`) on this hub layout — can't click-through the item name itself to reach a real detail page from here.
  - a stray click near this page's top-right "close"(X) icon area can accidentally trigger a LOGIN MODAL(real incident: closing an unrelated popup surfaced "등록/로그인" w/ Google/Kakao/Passkey options) — ALWAYS verify what you're clicking near modals, close via the actual X/close button(`AXButton "Close"`, found via a11y not guessed) and NEVER proceed through a login-prompt.
  ★MITIGATION: if a product-card click lands on this hub-page pattern, DON'T fight it — go back to the ORIGINAL search-results tab(if still open, switch via tab-click; verify via a11y `AXWindow` title before clicking, tab-bar clicks are position-sensitive and easy to mis-click) and pick a DIFFERENT candidate whose link routes to a normal `/item/` page instead. Simpler than debugging the hub-page's separate cart flow.
