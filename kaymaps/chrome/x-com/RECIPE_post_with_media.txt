RECIPE: post_with_media(X.com via Chrome)
REG: a_1039(2026-08-20) — UI 학습 단계, 실제 게시(Post 클릭)는 미수행(범위 외)
SEE-ALSO: [[chrome_common]](kaymaps/chrome/_common/RECIPE_chrome_common.txt) — Chrome 열기/새탭/주소창/DevTools 등 사이트 무관 공통 조작.

WHY: kongtrol input 계열은 항상 --yes 필수(a_1035~1037, RiskLevel::Dangerous 설계).

STEPS(Chrome 열기~X.com 접속):
1. Chrome 열기 = Spotlight 경유(cmd+space→"Google Chrome"→return). Dock/메뉴바 좌표 불안정(AlDente 사례) 대비 권장.
2. 새 탭: `input chord cmd t --yes`. 주소창 자동포커스 상태에서 `input text "x.com" --yes`→`input key return --yes`.
3. ★함정: 페이지 로드 전에 텍스트 입력하면 포커스가 페이지 내 필드(로그인 이메일칸 등)로 넘어가 오타 유입 가능 — 로드 완료(sleep 2s+) 후 주소 입력 권장.

LOGIN-STATE(2026-08-20 확인):
- 비로그인 상태 → "지금 일어나고 있는 일" 랜딩+로그인 폼 표시(전화번호/Google/Apple 계속하기 버튼 + 이메일-또는-사용자이름 텍스트필드).
- a11y 확인된 로그인 옵션: AXButton "전화번호로 계속"(590,597) / AXButton "Google 계정으로 계속하기"(590,660, 새탭 열림, "Continue as 살자, panic.hill@gmail.com" 버튼 포함) / AXButton "Apple로 계속"(590,729).
- ★로그인 자체는 이 레시피 범위 아님(a_1039는 UI학습까지만, 계정 자격증명 입력은 사용자 판단 필요 시 별도 a_ 필요).

LOGIN-PROCEDURE(a_1040 검증완료, Google 계정 원클릭):
1. "Google로 계속" 버튼 클릭(비로그인 랜딩, a11y AXButton "Google 계정으로 계속하기").
2. Google 계정선택 팝업(별도 윈도우, "로그인 - Google 계정") 등장 → 대상 계정 링크 클릭(a11y `AXLink "<이름> <email>"`, 예: "차카게살자 panic.hill@gmail.com").
3. 팝업 자동 닫힘 + x.com/home으로 리다이렉트(로드 3~4초 소요, sleep 필요).
4. ★함정: 클릭 직후 즉시 재조회하면 이전 페이지 a11y가 캐시처럼 보여 "안 눌렸다"고 오판하기 쉬움 — 매 클릭 후 최소 3s 대기 후 재조회.

POST-LOGIN UI(a_1040 검증완료, 홈 피드 상단 인라인 작성 박스 기준):
- AXTextArea "게시물 본문"(969,216) — 텍스트 입력 필드, placeholder "무슨 일이 일어나고 있나요?".
- AXButton "사진 또는 동영상 추가"(722,272) — 미디어(이미지/동영상) 첨부.
- AXButton "GIF 추가"(762,272).
- AXButton "이미지 생성"(802,272) — AI 이미지 생성.
- AXButton "투표 추가"(842,272).
- AXButton "예약 게시물"(922,272).
- AXButton "위치 태그하기"(962,272).
- AXButton "게시하기"(1185,272) — ★실제 게시(공개), 이 레시피 실행 시 항상 신중 — 사용자 명시 승인 없이 클릭 금지.
- ※좌표는 홈 피드 스크롤 위치·창 크기에 따라 달라질 수 있음 — 매번 `see --a11y --pid <PID> --yes` 재조회 권장(하드코딩 좌표 그대로 재사용 금지).

TEXT-INPUT-함정(a_1043 실증):
- 인라인 홈피드 작성창(AXTextArea "게시물 본문")에 개행 포함 `input text`로 긴 텍스트 입력 시 **X.com이 자동으로 스레드(연속 트윗)로 분할**하는 버그성 동작 발생(개행마다 새 트윗박스 생성). 반드시 **개행 없는 한 줄 텍스트**로 입력(문단 구분은 " · " 등 구분자로 대체).
- `input chord cmd v`(붙여넣기)는 X.com 입력창에서 반응 없음(클립보드 연동 안 됨, pbcopy 클립보드와 무관) — `input text` 직접 타이핑만 신뢰.

MEDIA-ATTACH-절차(a_1043 실증, macOS 파일선택 다이얼로그):
1. "사진 또는 동영상 추가" 버튼 클릭(1회로 안 뜨면 재클릭 — 클릭 씹힘 가능성 있음, a11y 재조회로 버튼 좌표 재확인 후 재시도).
2. macOS 표준 파일선택 시트(NSOpenPanel) 등장 — 이전 방문 폴더가 기본 표시됨.
3. ★검색 활용 권장: 우측 상단 검색필드(a11y `AXComboBox "검색어"`) 클릭 후 파일명 일부 `input text`로 검색 → 결과 리스트에서 대상 파일 클릭(선택시 파란 하이라이트+우측 미리보기+"열기" 버튼 활성화로 확인) → "열기"(우측 하단, 파란 버튼) 클릭.
4. 첨부 후 "<파일명>: 처리 중" 배너 표시 → 사라지면(수 초~10여초) 업로드 완료. 완료 전 창을 닫으려 하면 "아직 동영상을 업로드하는 중입니다" 확인 다이얼로그 뜸(§DRAFT-SAVE 참고).
5. ★좌표 스케일 주의: Read 도구가 반환하는 이미지 크기 ≠ screencapture 실제 pt 좌표 — crop 영역(-R x,y,w,h)과 표시 이미지 크기 비율로 정확히 역산 필요(단순 눈대중 클릭은 반복 실패, [[screenshot_coord_conversion]] 참고).

★★DRAFT-SAVE-절차(a_1043/1045 실증, 정식 게시 없이 임시저장):
1. 텍스트+미디어는 반드시 **좌측 사이드바 "게시하기" 버튼**으로 여는 **별도 컴포즈 모달**(`x.com/compose/post`)에서 작성(홈피드 인라인 작성창은 새로고침 시 내용 소실, 자동 draft 저장 안 됨 — a_1043에서 실증 확인).
2. 텍스트 입력(위 TEXT-INPUT-함정 준수) → 미디어 첨부(위 MEDIA-ATTACH-절차) → 업로드 "처리 중" 문구 사라질 때까지 대기(완료 확인).
3. 모달 좌측 상단 **X(닫기) 버튼** 클릭.
4. 업로드 미완료 시: "잠시 생각을 정리합니다 — 아직 동영상을 업로드하는 중입니다..." 다이얼로그 뜸 → **"계속"** 클릭(취소 아님, 작성 유지) → 업로드 완료까지 대기 후 다시 X 클릭.
5. 업로드 완료 후 X 클릭 시: **"게시물을 저장할까요? — 이 내용을 저장한 후 나중에 초안에서 전송할 수 있습니다."** 다이얼로그 → **"저장"** 클릭(★"삭제하기"를 누르면 완전 삭제되니 주의).
6. 검증: 좌측 사이드바 "게시하기" 버튼으로 새 컴포즈 모달 열기 → 우측 상단 **"초안"** 링크 클릭 → "전송하지 않은 게시물" 탭에서 저장된 draft(텍스트+영상 썸네일) 확인.
7. ★Post/게시하기 버튼은 이 전체 절차에서 한 번도 클릭 안 함 — 완전한 임시(비공개) 상태 유지.

VERIFY:
- 로그인 상태 판별: a11y에 "전화번호로 계속"/"Google 계정으로 계속하기" 버튼 존재 = 비로그인. 부재+"게시물 본문" AXTextArea 존재 = 로그인됨.
- 텍스트 입력 후 확인: `input text "<내용>" --yes` 후 zoom-crop 또는 a11y AXTextArea value로 오타/누락 확인. 스레드 분할 여부(여러 트윗박스 생성됐는지)도 반드시 확인.
- 미디어 첨부 후: 첨부 썸네일이 작성박스 내 새 AXImage/AXGroup으로 나타나는지 a11y 재조회로 확인, "처리 중"→소멸 확인.
- Draft 저장 후: "초안" 탭에서 실제 항목 존재 확인(스크린샷 증거 필수).
