UI_MECHANISM: Keynote 전반 좌표계·조작 메커니즘 통합 문서
등록: a_488 / u_505 (2026-08-16)
용도: Keynote 순수 IO 조작 시 매번 처음부터 분석하지 않고 바로 참고

=== 1. 좌표계 (실증 완료, 2026-08-16) ===
- kongtrol의 `input click <x> <y>` / `input move <x> <y>` 는 **논리좌표(scale 1.0)** 를 그대로 받는다.
- `kongtrol see --a11y --compact --pid <PID>` 가 출력하는 좌표는 이 논리좌표계와 동일 → **a11y가 준 좌표를 그대로 click에 넣으면 정확하다.**
- 스크린샷(screencapture) 이미지는 **물리 픽셀** 해상도(예: 4112x2658). 논리좌표 = 물리픽셀 ÷ 2 (Retina 배율 2.0 확인됨, calibration: a11y (611,339)*2 = 물리(1222,678) = 실제 아이콘 위치 일치).
- 스크린샷에서 직접 좌표를 잴 때: 물리픽셀 좌표를 구한 뒤 **2로 나눠서** click에 사용.
- BAN: 배율을 눈대중으로 곱하거나 스크린샷 "표시 크기"(도구가 다르게 리사이즈해서 보여주는 값)를 기준으로 계산하지 말 것 — 반드시 원본 이미지 픽셀 기준.

=== 2. 정렬 탭 (X/Y/W/H numeric 입력) ===
탭 위치: 인스펙터 상단 3개 탭("스타일"/"텍스트"/"정렬") 중 "정렬" 클릭 후 a11y dump로 재확인.
필드 순서(a11y dump 예시, 전체화면 83% 줌 기준 — 창 크기/줌 바뀌면 매번 a11y로 재확인 필수):
  AXTextField <W>pt  (예: 1903,266) — 너비(Width)
  AXTextField <H>pt  (예: 1992,266) — 높이(Height)
  AXTextField <X>pt  (예: 1903,346) — X좌표
  AXTextField <Y>pt  (예: 1992,346) — Y좌표
  AXTextField <곡률>pt (예: 1994,503) — 둥근사각형 모서리 곡률(있는 도형만)
입력 절차(각 필드 공통): click 필드좌표 → wait 300ms → cmd+a → text 새값 → key enter
정확도: 현재 표시값(pt)으로 어느 필드인지 구분 가능. 필드 클릭 없이 바로 cmd+a 금지(캔버스 전체선택 사고 발생 이력).
상세: RECIPE_resize_textbox_width.txt

=== 3. 도형 생성 ===
도구모음 "도형" 버튼(메뉴바 아이콘 열, 대략 논리좌표 1056,72 — 전체화면 기준, 줄바뀌면 a11y로 "도형" AXCheckBox 재확인) 클릭 → 팔레트 열림.
팔레트 구성: 카테고리 리스트(좌측: 기본/기하학/사물/동물/자연/음식/기호/교육/예술/과학/사람/장소/활동) + 도형 그리드(우측).
"기본" 카테고리 그리드 1행: 사각형/둥근사각형/원, 이하 화살표/삼각형/별 등.
클릭하면 캔버스 중앙 부근에 기본 크기(100x100pt)로 자동 생성됨 → **즉시 정렬 탭으로 이동해 목표 좌표로 numeric 배치**(대충 위치 잡고 나중에 옮기지 않는다 — a_486 원칙).
상세: RECIPE_shape_create_and_place.txt

=== 4. 텍스트박스 ===
- 위치조정: 도형과 동일하게 정렬 탭 X/Y/W/H numeric.
- 색상 대비 주의: 텍스트 생성은 정상 동작해도 텍스트색과 배경색 대비가 0에 가까우면 안 보임(흰 배경+흰 텍스트 등). 반드시 배경과 대비되는 색 지정.
- Width 줄바꿄 버그: 텍스트가 길어 줄바꿈되면 Width를 +40씩 기계적으로 늘려 해결(최대 3회, a_463 규칙).

=== 5. 색상 지정 (Hex 직접 입력 — 2026-08-16 확립, a_485) ===
1. 도형/텍스트박스 선택
2. 스타일 탭 → "채우기" 항목 펼침 → 채우기 색상 스와치 옆 **무지개 아이콘**(작은 원형 버튼, a11y 미노출 — 스크린샷에서 채우기 스와치 바로 우측 확인 후 클릭) 클릭
3. macOS 표준 색상피커 팝업(별도 창) 열림 → "RGB 슬라이더" 탭에 **"16진수 색상 #" 입력 필드** 존재
4. 그 필드 click → cmd+a → 6자리 Hex(예: 9AA0A6, 4285F4, 4A4A4A) 입력 → Enter
5. 색상피커 좌상단 빨간 X로 닫기
정확도: Hex 입력 = 100% 정확, 프리셋 스와치 육안 클릭보다 신뢰도 높음(프리셋은 페이지 2에 회색 계열 있으나 클릭 시 "새 스타일 추가" UI라 실색상 아님 — 함정 주의).
상세: RECIPE_set_fill_color.txt

=== 6. 전체화면 적용/종료 ===
시작: 메뉴 "보기"(논리좌표 419,20) 클릭 → "전체 화면 시작" 메뉴아이템 클릭(a11y로 좌표 재확인, 팝업 위치 매번 다를 수 있음).
전체화면 상태에서 Esc 키를 누르면 전체화면이 풀리므로 **Esc는 전체화면 유지 중엔 사용 금지**(강제종료 대화상자 대응 등 다른 목적으로도 Esc 쓰지 말 것 — 대신 해당 UI 고유 버튼 사용).
상세: RECIPE_fullscreen_apply.txt

=== 7. Keynote 세션 시작/종료 ===
시작(문서 열기): RECIPE_session_start.txt — 파일 열기 → 즉시 전체화면 → 연속 작업.
종료: Cmd+Q 무반응 이력 있음 → 메뉴 "Keynote" → "Keynote 종료" 클릭으로 성공. 상세: RECIPE_quit_keynote.txt

=== 8. 강제종료(응용 프로그램 강제 종료) 대화상자 ===
발생 원인: 시스템 메모리 부족 경고. loginwindow(PID는 매 세션 다름, pgrep -x loginwindow로 확인) 소유의 시스템 레벨 대화상자.
최종 규칙(a_479 확정, a_476/477/478 무효화됨):
  1. "일시 정지됨"(붉은색) 표시 앱 있으면 클릭 선택 → "재개" 버튼 클릭 시도(활성화 안 될 수 있음 — 그 경우 다음 단계로)
  2. 안 되면 좌상단 빨간 X(닫기) 버튼 시도(정밀 좌표 필요 — 물리픽셀 red-color 검출로 재계산 권장)
  3. 그래도 안 닫히면: 강제종료 절대 금지, 대기(수십 초~수 분) 후 메모리 회복되면 대화상자 자동 소멸하는 경우 있음 — 재확인
  4. 대화상자로 인해 Keynote 프로세스 자체가 죽는 경우 있음 → 문서 파일은 iCloud 자동저장으로 보존됨(~/Library/Mobile Documents/com~apple~Keynote/Documents/) → 재오픈하면 복구
BAN: 어떤 상황에서도 프로세스 강제종료 버튼 클릭 금지(a_477/479 최종 확정 — 초기 a_476 "빨간색 강제종료" 지시는 오해였고 철회됨).
상세: RECIPE_force_quit_dialog.txt
